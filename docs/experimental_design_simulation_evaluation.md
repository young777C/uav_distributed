# 实验设计：无人机巡检「路径规划 + 数据回传」与仿真/评价对齐指南

## 0. 研究场景与系统边界

### 0.0 地面控制站（GCS）

**GCS 设在起降点**（与 `start_ne` 同址，YAML 可写 `gcs_ne`）。UAV 与 GCS 的职责分工、快慢环对应关系见 **`docs/uav_gcs_collaboration.md`**。

### 0.1 任务定义

本研究面向 **无人机巡检任务**：在含障碍/禁飞约束的环境中，按任务点（POI）顺序完成巡视，并在飞行过程中将 **任务数据**（可抽象为图像/视频/检测结果等）经 **上行链路** 回传地面。策略需同时优化：

- **路径与运动**：慢环全局访问顺序 + 快环局部航迹/速度微调，保证安全到达各巡检点；
- **数据回传**：在通信退化条件下分配回传资源，优先保障 **高价值数据** 的及时交付。

### 0.2 机载能力假设（与实验契约强相关）

本课题主要依赖四类机载信息/能力，训练环境与后续 PX4+Gazebo 仿真应对其 **语义与更新率** 对齐：

| 模块 | 在任务中的作用 | 与当前抽象环境的关系 |
|------|----------------|----------------------|
| **GPS** | 全局/局部平面位置，用于相对子目标距离与方向 | 对应 `pos (n,e)`、观测中 `dN,dE,dirN,dirE`；仿真需统一 NE/NED 与原点 |
| **IMU** | 姿态角速度、加速度；与飞控融合后提供姿态/短时速度辅助 | 当前观测以 **平面速度 + yaw** 表征；高保真仿真可由 EKF 输出与训练约定一致的 `Vn,Ve,yaw` |
| **（可选）视觉/检测** | 巡检目标检测、触发/标记「高价值」数据 | **当前 TaskAEnv 观测不含射线 `rays`**；障碍/禁飞由 **场景几何 + env 碰撞/禁飞判定** 处理；观测中仅含 **最近禁飞边界的距离与方向**（`dist_nf`, `dir_nf*`）。高价值数据仍以 **key chunk / key_pending** 抽象。若未来接 Gazebo，可用检测/地理围栏信号对齐 `key_pending` 语义。 |
| **通信模块** | 控制/状态闭环链路 + 任务数据上行；延迟、丢包、带宽 | 对应 `CommChannel` + 双链路指标 + `comm`/`data` 观测块；可与实机 trace 或外挂链路模型对齐 |

**设计要点**：训练不要求内建 Gazebo 几何，但 **GPS/IMU/Camera/通信** 在观测向量中的 **含义、坐标系、噪声模型** 必须与后续仿真/实机评价合同一致，否则策略无法可靠迁移。

## 1. 设计原则

| 原则 | 说明 |
|------|------|
| **单一事实来源** | 巡检场景几何（任务点、最终目标、禁飞、边界）以 `configs/taskA/scene/*.yaml` 为权威；Gazebo world 与 POI 摆放应与此一致（生成或人工校验）。 |
| **观测契约** | 每一维观测对应「哪类传感器/估计器输出」应文档化（见第 2 节映射表）；PX4+Gazebo 侧按同一顺序、坐标系、归一化填充。 |
| **动作契约** | 快环输出应对应 **Offboard 速度设定 + 软件定义的回传调度**；与 PX4 模式及地面站/机载协议一致。 |
| **双链路区分** | **控制/状态闭环**（deadline-sensitive）与 **任务数据上行**（吞吐/完整率）在指标与日志中分开记录（见 `docs/dual_link_metrics_design.md`）。 |
| **可复现** | 固定 `seed`、保存 `resolved_config.yaml`、记录通信 profile、场景与 world 版本。 |

## 2. 传感器 → 观测向量映射（`append_comm_to_obs=True`）

**总维度**（`append_comm_to_obs=True`）：基础 **11** + 通信/数据/快环扩展 **11**（comm 5 + data 3 + fast_extra 3）→ **22**；若 `append_energy_budget_to_obs=True` 再 **+3** → **25**。  
实现：`uavlab.tasks.taskA.env.TaskAEnv._build_obs`。

### 2.1 导航与姿态相关（GPS + IMU 融合结果的抽象）

| 观测索引 | 内容 | 典型传感器来源 | 仿真/PX4 对齐建议 |
|----------|------|----------------|-------------------|
| 0–1 | `dN`, `dE` | GPS/全局位置 + 子目标（慢环+快环有效目标） | 同一水平面定义；有效目标与训练一致 |
| 2–3 | `dirN`, `dirE` | 由上式导出 | 与 dN、dE 同系 |
| 4–5 | `Vn`, `Ve` | GPS 多普勒/融合速度或光流辅助 | MAVSDK `velocity_ned` 等转换到 NE 平面 |
| 6–7 | `yaw_sin`, `yaw_cos` | IMU/磁力计/融合航向 | **固定约定**：用融合 yaw 或速度方向，训练与评价必须相同 |

### 2.2 环境与巡检安全（地图几何，无射线观测）

| 观测索引 | 内容 | 典型来源 | 仿真对齐建议 |
|----------|------|----------|--------------|
| 8–10 | `dist_nf`, `dir_nfN`, `dir_nfE` | GCS/机载持有的 **电子地图**（禁飞多边形/围栏）+ GPS 位置 | scene YAML 与 Gazebo 禁飞几何一致；与 `nearest_nofly_dist_dir` 计算一致 |

### 2.3 通信模块 → 链路状态与数据面（双业务）

| 子块 | 维数 | 内容 | 说明 |
|------|------|------|------|
| comm | 5 | aoi, l_out, pdr, 控制队列长, bw_utilization | 对应 **控制/状态闭环链路** 的统计，与 deadline 类指标一致 |
| data | 3 | 本地队列、在途队列、key_delivery_ratio | **任务数据上行**（图像/视频等抽象为 chunk）；高价值比例与巡检「关键点」策略一致 |
| fast_extra | 3 | battery_ratio, mean_delay_s, key_pending | 能量约束；控制链路延迟；**待上传高价值数据**积压（与 Camera/检测触发逻辑可对齐） |

**高价值数据（任务点定义）**：默认 **`data_key_mode: poi`**。当 **`poi_list` 非空** 时，仅在 **POI/星标任务点** 半径内（`key_data_radius_m` 等）采集为 **key**；**起降点（与 goal 重合时）不算 POI**，不产生高价值标记。若 `poi_list` 为空则回退为 **goal** 周围（旧场景兼容）。详见 `docs/scene_experiment_world.md`。

**通信退化区域**：场景 YAML 中 **`communication_blackholes: [[n, e, r], ...]`** 会传入 `CommChannel.blackhole`，与 `base_loss` 叠加，与障碍物几何独立预设。

## 3. 动作空间与机载执行（快环 5 维）

| 索引 | 含义 | 与巡检+回传的关系 | PX4+Gazebo |
|------|------|-------------------|------------|
| 0–1 | `delta_n`, `delta_e` | 相对慢环子目标的 **局部航迹微调**，规避局部障碍或优化观测站位 | 与任务点坐标系一致 |
| 2–3 | `vn_cmd`, `ve_cmd` | **局部速度指令**，由飞控内环（IMU 闭环）跟踪 | Offboard velocity，NED↔NE 固定转换 |
| 4 | `send_ratio` | **高优先级任务数据上传**调度强度（配合 key 优先队列） | 机载通信栈或抽象网关；实机需定义与无线资源的对应关系 |

## 4. 快慢环在巡检任务中的分工（实验记录建议）

| 层级 | 时间尺度 | 输入侧重 | 输出 | 实验中要记录的配置 |
|------|----------|----------|------|-------------------|
| **慢环** | 分钟 / 任务段 | 全局 POI 列表、全局位置（GPS）、链路约束、环境（地图/禁飞） | 下一访问点 + `DataStrategy`（批量、压缩、优先级） | `slow_interval_steps`、POI 顺序策略、默认 `batch_size`/`compression_ratio` |
| **快环** | 秒 / 步 | 局部状态、局部链路、待传 key、最近禁飞几何摘要 | 航点微调 + 速度 + 上传比例 | `step_hz`、`waypoint_delta_max`、观测是否含 comm/data |

## 5. 场景与配置（巡检场地）

- **场景文件**：`scene_file` 含 `poi_list`、`goal_ne`、禁飞、边界；版本写入实验笔记。
- **Gazebo**：world 中巡检点、杆塔/设备模型位置与 YAML 一致；GPS 原点与 NE 定义一致。
- **训练与评价**：共用 `resolved_config.yaml` 结构；评价时可仅改通信强度、回合长度、种子。

---

## 6. 时间尺度与控制频率

- **控制周期**：`step_hz` 与 PX4 offboard 频率一致或整数倍关系，并文档化。
- **IMU**：远高于控制周期；策略步内不需要原始 IMU，但需要明确 **状态估计输出频率** ≥ 控制频率。
- **Camera**：曝光与帧率可能低于控制频率；若用下采样或异步 buffer，须在契约中说明观测用的是「最新帧」还是「步内均值」。

---

## 7. 通信与数据面（巡检业务）

- **控制/状态链路**：与飞控安全相关，参数与 `control_*`、`CommMetrics` 一致；评价时注明抽象模型或 trace 驱动。
- **任务数据链路**：对应图像/视频回传抽象；指标见 `task_*` 与公式.txt（goodput、完整率、经济性、速率稳定性）。
- **trace**：现场或仿真录制 trace 时，记录 GPS 位置与链路事件，便于与论文图表对应。

---

## 8. 评价与测试流程（建议）

1. **阶段 A（抽象环境）**：`eval` / `taskA_sweep`，验证策略与通信退化曲线。  
2. **阶段 B（传感器级 sim-to-sim）**：Gazebo 提供 GPS/IMU/Camera（或激光）→ 装配与训练相同维度的 obs；先对比无通信随机下的轨迹与 obs。  
3. **阶段 C（完整巡检指标）**：成功率、数据完整率、关键帧到达率、任务时长、能耗 proxy（battery）等，与论文表述一致。

---

## 9. 域随机化与分布外

- 对 **GPS 噪声、IMU 偏差、Camera 噪声/遮挡、链路丢包/延迟** 做适度随机化，模拟真实巡检环境。  
- 评价报告 **训练分布内** 与 **更强退化/不同场景** 两档结果。

---

## 10. 常见陷阱清单（巡检 + 多传感器）

- [ ] NE / NED / 磁北与真北未统一，GPS 目标与 Gazebo 模型错位。  
- [ ] 禁飞/障碍几何与 GPS 坐标系不一致，`dist_nf`/碰撞判定与实机地图错位。  
- [ ] 高价值数据在训练为随机 key，实机为检测驱动，未做对齐说明。  
- [ ] 只测位置成功率、不报告 **数据完整率 / key 成功率**。  
- [ ] 控制链路与任务数据链路指标混在同一曲线未标注。  
- [ ] 动作维数（当前 **5**）与旧 checkpoint 不匹配。  
- [ ] 未保存 `resolved_config.yaml`，无法复现巡检场景与通信配置。
