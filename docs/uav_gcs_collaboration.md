# UAV 与地面控制站（GCS）协作与分工

## 0. 场景中的 GCS 位置

在实验场景里，**地面控制系统（GCS）设在起降点**：与 `configs/taskA/scene/default.yaml` 中的 **`start_ne`（起飞/降落）** 同址；也可在 YAML 中显式写 **`gcs_ne`**（若省略，加载时自动等于 `start_ne`）。  
几何上表示：**小圆 = 起降点 = GCS 基地**，UAV 由此出动、任务结束后归航至此。  
解析函数：`uavlab.scene.loader.resolve_gcs_ne(scene)`。

---

## 1. 通俗比喻

| 角色 | 比喻 |
|------|------|
| **GCS** | 指挥中心 / 后勤保障 |
| **UAV** | 前线巡检兵 / 移动采集器 |

---

## 2. UAV 主要职责

1. **按航线巡检任务点**（执行 GCS/慢环给出的子目标序列或全局航路）。  
2. **实时采集任务数据**（图像、视频、传感器等；仿真中用抽象 chunk + POI 区内高价值标记代替）。  
3. **快环局部航迹微调**：避障、应对局部链路退化（速度设定 + 航点微调 + 与感知/链路相关的观测）。  
4. **高优先级数据上传触发**：`send_ratio` 等，保证关键数据及时回传 GCS（抽象为上行队列与 `CommChannel`）。

**代码对应（当前仓库）**：`TaskAEnv` 每步 `step`、快环 5 维动作、`DataBuffer`/`Uplink`、局部观测中的 `comm`/`data` 块。

---

## 3. GCS 主要职责

1. **提供全局导航参考**：航线规划、任务调度（下一任务点、访问顺序）。  
2. **接收 UAV 上传的数据**：图像、传感器摘要、链路状态（仿真中对应 `info` 与指标落盘；双链路指标见 `docs/dual_link_metrics_design.md`）。  
3. **慢环 RL 或调度策略**：任务点访问顺序、上传策略（批量/压缩/优先级）、资源分配（如 `DataStrategy.batch_size` 等）。  
4. **通信链路监控**：链路健康、延迟、丢包等统计（控制链路与任务数据链路分开评价）。

**代码对应（当前仓库）**：`HeuristicSlowPlanner.plan()` → `PlannedTarget` + `DataStrategy`；`env.set_target()` / `env.set_data_strategy()`；训练时慢环可在外部脚本以固定间隔调用（如 `run_hierarchical`）。

---

## 4. 协作模式（与快慢环）

| 环节 | 谁主导 | 说明 |
|------|--------|------|
| 全局 | **GCS / 慢环** | 任务点顺序、回传策略参数、导航参考下发 |
| 局部 | **UAV / 快环** | 每步安全、即时回传强度、航迹微调 |
| 数据流 | **UAV → GCS** | 任务数据上行；**GCS → UAV** 控制/参考（仿真中合并为 `CommChannel` + 控制缓冲） |

- **UAV 前线**：按 GCS 下发的航线与策略执行；快环 RL 或规则保证**局部安全**与**即时任务数据上传**。  
- **GCS 后台**：全局调度 + 数据汇聚 + 资源优化；慢环 RL **可在 GCS 上算**（更符合工程部署），也可在仿真里与 UAV 同进程调用以简化接口。  
- **通俗**：UAV 执行任务和局部应急；GCS 做**战略规划**与**全局资源管理**。

更细的 I/O 见：`docs/fast_slow_loop_design.md`、`docs/data_flow.md`。

---

## 5. 与 `scene.jpg` / `default.yaml` 的关系

- GCS 位于**起降小圆**，UAV 从该点出发，穿越 POI 与退化区后**归航至同一点**着陆。  
- 链路上可理解为：**所有上行数据的接收端、慢环决策的发出端**均关联该基地坐标（距离、时延模型可在后续扩展为与 `resolve_gcs_ne` 相关的几何项）。
