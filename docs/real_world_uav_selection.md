# 实机验证无人机选型指南

> 面向 ACoT-UAV-Track 项目从 CARLA 仿真（`carla_uav_tracking/rollout/policy.py`、`policy_server.py`，crop-DINOv2 + K2 gallery re-ID 跟踪管线）向实机验证过渡的硬件选型参考。

## 一、核心约束

实机验证需要同时满足两个硬约束：算法能"接管"飞控（offboard 控制），机身能"装下"跟踪算法所需的算力/云台/图传。选型时优先确认这两点是否可行，再看其余维度。

## 二、选型考虑因素

### 1. 飞控开放性 / offboard 控制接口
最优先的一条。必须支持外部计算机通过 MAVLink（或厂商 SDK）以一定频率下发速度/位置指令，替代传统遥控。

- **开源生态**：PX4 / ArduPilot，配合 MAVROS/MAVSDK，offboard mode 成熟，可直接对接现有 `policy_server.py` 架构。
- **商业闭源**：大疆 Onboard SDK (OSDK) / MSDK，接口稳定但灵活性和延迟控制不如开源栈，部分接口存在黑盒限制。

### 2. 机载算力（companion computer）
re-ID（DINOv2 crop 特征）+ 策略推理需要上机跑，或至少做本地预处理再回传。

- Jetson Orin Nano/NX（8-16GB）是当前研究圈标配，功耗和重量可控。
- 若算力需求大，可采用"机上采集+压缩回传、地面站 GPU 推理、指令上传"的分离架构，但要实测端到端延迟和带宽是否满足实时跟踪要求。

### 3. 载重与轴距
Jetson + 云台相机 + 图传模块 + RTK 模块合计常超过 500g，普通 250 级穿越机挂不住。一般需要 ≥450mm 轴距、起飞重量留有 1.5kg 以上余量的平台。

### 4. 相机 / 云台
- 需要三轴增稳云台，将机身姿态与相机视角解耦，否则目标框抖动会污染 re-ID 特征。
- 分辨率、帧率、快门类型（全局快门优于卷帘快门）应尽量与 CARLA 仿真相机参数对齐，便于 sim-to-real 迁移评估。

### 5. 定位与真值获取
- 跟踪精度评估需要无人机自身位置真值，RTK GPS（厘米级）基本是必需的，便于和目标车辆 GPS/RTK 做相对误差评估。
- 室内测试需考虑 UWB 或动捕系统（如 OptiTrack/Vicon）。

### 6. 通信链路
- 图传延迟直接决定闭环跟踪的响应速度，优先选低延迟数字图传（如 DJI O3、SIYI 图传），避免普通 WiFi 图传（延迟/丢包大）。
- 遥测/指令链路应独立于图传，用于安全接管（急停、RTH）。

### 7. 安全冗余
- 独立遥控器物理接管权限（一键切回手动/RTH）。
- 地理围栏、失控保护（failsafe）。
- 室内测试建议加装桨叶保护罩，或先用更小机型降低风险。

### 8. 法规与场地
国内室外试飞需留意民航局适飞空域和实名登记（>250g 需登记，>7kg 或特定空域需申请飞行计划）；室内测试更便于迭代，但需动捕或视觉定位保证安全。

### 9. 生态与可维护性
优先选社区活跃、文档全、与 ROS2/MAVSDK 集成度高的平台，便于问题定位，避免厂商黑盒 SDK 报错无从下手。

### 10. 预算与迭代成本
建议先用便宜、易损耗的平台在真实动力学噪声下把算法跑通，再迁移到抗摔性差但更精密的平台做最终验证，避免早期试错阶段损坏高价设备。

## 三、机型推荐

| 用途 | 推荐 | 说明 |
|---|---|---|
| 室内/低成本算法冒烟测试 | DJI Tello / Tello EDU | 几百元级，Python SDK 好上手，可验证控制指令链路和基本跟踪逻辑；载重接近零，跑不了机载 DINOv2 推理，只适合"云端推理+机上执行"架构验证 |
| **DIY 研究平台（主力方案，推荐）** | Holybro X500 V2 / S500 机架 + Pixhawk 6C 飞控 + Jetson Orin Nano/NX 机载电脑 + SIYI A8 mini 或 ZR10 云台相机 | PX4 + MAVROS 全开源，offboard 控制成熟，社区案例多，载重和算力均够用，成本可控（整套约 2-4 万元），最适合自定义 re-ID/policy 推理管线 |
| 官方参考套件 | Holybro PX4 Vision Dev Kit | 官方针对视觉自主飞行设计，自带双目相机 + Jetson，开箱即用 PX4+ROS2 栈，省去自行攒机调试成本 |
| 工业级/更稳的室外验证 | DJI Matrice 300/350 RTK + Zenmuse 云台相机 + OSDK 接机载电脑 | 抗风、续航、RTK 精度顶级，云台稳定性好，适合最终展示级实验；缺点是 SDK 灵活性较差、价格高（十几万+），指令延迟/接口自由度不如 PX4 栈 |
| 固定翼/长航时 | 不建议 | 本项目任务是类似"跟随地面车辆"的近距离机动跟踪，旋翼平台的悬停和低速机动能力更重要 |

## 四、针对本项目的落地建议

结合现有 `policy_server` + re-ID（crop-DINOv2 + K2 gallery + confidence gate）架构，建议路线：

1. 先用 **Holybro X500 + Pixhawk 6C + Jetson Orin NX** 搭建研究机，PX4 offboard 模式对接现有 policy_server 的指令输出接口，改动量最小。
2. 云台相机选支持 UART/网口取视频流的型号（如 SIYI A8 mini），便于直接接入现有 crop pipeline。
3. 先在室内小范围/低速场景验证控制闭环和 re-ID 在真实噪声（运动模糊、光照变化）下的鲁棒性，再逐步扩展到室外、更接近 CARLA `road_expert` 场景的开放道路跟车测试。
4. 目标车辆一侧建议挂一个 RTK GPS 模块，用于评估跟踪误差真值。
