# 高分辨率重渲 spec(给数据 agent)—— reid 分辨率探针的 >512 数据

> 2026-09-01 · 配套 `train/reid_resolution_probe.py` + memory `acot-uav-reid-reframe`
> **目的**:验证"WHICH(重捕获认车)被外观可分性/分辨率卡死"这一根因是否可解——需要 **>512 渲染**的一小批验证集。512 数据已封顶(网格 16×16、reid mis_follow 0.578、look-alike 余弦 0.877,抬 max_pixels 无效)。

---

## 0. 为什么要重渲(一句话)
目标车在 512 帧里 ~24px,Qwen 网格 16×16 → **每辆车只占 ~1 个格子** → look-alike 特征余弦 0.877(近乎同一向量)→ reid 认车 0.57 天花板。**只有让车有更多真实像素**(>512 渲染 → 32×32/48×48 网格 → 每车占多格)才可能可分。抬 max_pixels 在 512 图上无用(无更多像素)。

## 1. 要什么(最小集)
**重渲 val-split 的一小批 episode**(**3–6 集足够**;探针用 4 集 stride6 = ~850 样本已稳),**每集渲两档分辨率**:
| 档 | 分辨率 | Qwen 网格 | 目标车像素 |
|---|---|---|---|
| A | **1024×1024** | 32×32 | ~48px(占 ~1.5 格) |
| B | **1536×1536** | 48×48 | ~72px(占 ~2.25 格) |

> 两档是为了画出 16→32→48 的趋势曲线,判断 mis_follow 是否继续跌破 0.5。若磁盘紧,先只做 A(1024)。

## 2. 关键:必须是"仅分辨率变化"的受控重渲
- **复用完全相同的 episode 场景/种子/轨迹**(CARLA sync 确定性)——同一批 val 集的 seed,只把**相机渲染分辨率**从 512 改成 1024/1536,其余(目标车、look-alike、轨迹、相机位姿、丢失窗口)**逐帧一致**;
- 这样 reid mis_follow 的变化**只归因于分辨率**,不引入场景协变量。

## 3. 输出(探针要读的字段,尽量沿用现有 h5 结构)
每集一个 h5(或在原集加高分辨率 RGB 组),**必须含**:
| 字段 | 说明 | 随分辨率变? |
|---|---|---|
| `rgb` | (T, R, R, 3) uint8,R=1024/1536 | **是**(核心) |
| `target/tx,ty,tz` | 目标世界位 | 否(世界系,直接沿用) |
| `state/cam_{x,y,z,pitch,yaw}` | 相机位姿 | 否(沿用) |
| `distractors/positions` | (T,D,6) 干扰车世界位 | 否(沿用) |
| `distractors/similar` | (D,) look-alike 标志 | 否(沿用) |
| `f.attrs['language']` | 目标描述 | 否(沿用) |

> `target_id/road_pred/action` 等**这个探针不需要**——只做外观可分性离线测,不跑控制/训练。位姿与世界位是分辨率无关的,直接从原 mvp_full_v5 对应集拷贝即可;**唯一真正要重渲的是 `rgb`**(+ 若存像素级 bbox 则按新分辨率重投影,但探针用 project_point 自己算框,可不存)。

## 4. 存储与命名
- 建议独立目录 `mvp_highres_v5/`,文件名带分辨率:`episode_{id}_r1024.h5` / `_r1536.h5`;
- **不覆盖** mvp_full_v5;
- 磁盘预估:1024 RGB ≈ 3MB/帧×1500 ≈ 4.5GB/集;1536 ≈ 10GB/集。**3–6 集 × 两档 ≈ 30–90GB** —— 7T 盘 99% 满,**先确认有 ~100GB 空闲**,不够就只做 1024 或减集数。

## 5. QC(交付前自查)
1. **同轨迹**:高分辨率集的 `target/tx[t]` 与原 512 集**逐帧一致**(证明只改了分辨率);
2. **分辨率正确**:`rgb.shape[1]==1024/1536`;
3. 随机抽帧目视:目标车在 1024 里明显更大更清晰。

## 6. 交付后我方对接
数据一到,我立即 `python -m train.reid_resolution_probe --config ... --split val`(指向新目录),扫 1024/1536 的网格,出 **reid mis_follow vs 网格分辨率(16→32→48)曲线** + look-alike 余弦。
- **mis_follow 继续跌、余弦下降** → 分辨率是完整答案,SR 路径 = 高分辨率(+可能 track+reid 全闭环);
- **饱和不跌** → look-alike 外观本征不可分(物理墙),转叙事。

---

## 附:成本备注(供排期判断)
- **只影响冻结 VLM 编码**(~4× @1024),**不影响可训练头**(它们吃 g=16 固定 256-token context);
- 全量重渲整个训练集才会撞磁盘(缓存 4×→~600GB);**本 spec 只要几集验证集,零风险**;
- 若探针证实分辨率有效,再评估"是否值得全量高分辨率重渲 + 重建缓存"的大投入。
