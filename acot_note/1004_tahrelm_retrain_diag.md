# 1004 TAHRelM 是否需要重训：误差归因 + 上界诊断(2026-10-03)

> **结论：暂不重训 TAHRelM**,保留 `runs/tah_relm_dag.pt`。
> - 它在记忆干净时的单步判别力接近离线水平。
> - 即使有一个**完美**的「目标不在候选中」检测器，三项客观指标的上界提升也有限，并且都不显著。
> - 目标缺席期间的主要问题在「往哪看」(WHERE)和跟踪器 ID 稳定性，而不在 TAHRelM 选哪辆车。
>
> 所有数字都来自 dev 91000–19 的全长闭环，与最终模型 v1(属性开局 + TAHRelM + PGIF,部署设定 v2)逐种子配对。

## 1. 误差归因(`carla_uav_tracking/rollout/tah_need.py`,v1 臂 n = 19,1172 个 S2 tick)

| 身份错误 tick 的来源(共 521) | 占比 |
|---|---|
| 目标不在候选中(被遮挡或出画，占全部 tick 的 38%),却承诺给了干扰车 | 54% |
| 目标可见,TAHRelM 原始选择错误,PGIF 跟随 | 28% |
| 目标可见但弃权 | 13% |
| TAHRelM 选对，被 PGIF 改错 | 5% |

- **记忆干净时的单步准确率**(上一步承诺正确，且两步目标都可见，n = 458):TAHRelM 原始选择 0.884,经 PGIF 后 0.928。离线验证集为 0.909。
- 目标重新出现后的前 5 个 tick,原始准确率为 0.51。一旦错一步，恢复概率只有 0.16(吸收态)。
- **训练分布与部署不一致**:训练用的 cache 和 DAgger(2026-09-08)都是 gt-seeded 或 teacher-forced 记忆、仿真 ID、不过滤遮挡。被遮挡的目标在训练里始终是带标签的候选，所以模型从没学过「目标不在」。

## 2. 上界诊断(只用于诊断，用到真值，不可部署)

| 臂 | 做法 | 承诺正确 Δ | 最长连续正确 Δ | 最长锁错 Δ | 集长 Δ(步) |
|---|---|---|---|---|---|
| v1(参照) | — | 0.646 | 15.8 s | 8.7 s | 513 |
| 诊断一 `ORACLE_ABSENT=1` | 目标不在候选中 → 强制弃权：保持承诺、撤销记忆写入、回滚 PGIF 证据;WHERE 匀速滑行 | **+0.115 [−0.010, +0.248]** | −2.6 [−8.7, +3.3] | −2.4 [−5.9, +1.3] | −41 [−142, +47] |
| 诊断二 `ORACLE_ABSENT=2` | 目标不在候选中 → 承诺和控制照常，但不写记忆、不累积 PGIF 证据 | −0.085 [−0.206, +0.019] | −5.0 [−11.5, +1.5] | +3.5 [−1.5, +9.0] | −25 [−141, +87] |

配对 n = 19,种子 bootstrap 95% CI。运行脚本为 `runs/opening_dump/f_oracle_absent.sh` 和 `f_oracle_hyg.sh`;对应的臂是 `zoo_pgif_trk_*` 和 `zoh_pgif_trk_*`。对比脚本 `runs/opening_dump/oracle_cmp.py <zoo|zoh> --full`。

**解读**
- 诊断一是给 TAHRelM 加一个**完美**「目标不在」输出的上界。它只把承诺正确提高约 0.12(CI 下界略低于 0),最长锁错下降不显著，最长连续正确不升反降。
  - 原因：弃权后 WHERE 只能匀速滑行，目标更容易出画，而目标连续出画 18 s 就终止 episode(`config/default.yaml` 的 `max_lost_seconds: 18`)。前 5 集里，集长从约 546 步降到约 302 步。
  - 一个**学出来的**检测器做不到完美，实际收益会更小。
- 诊断二(只禁止「从干扰车学习」)没有改善，方向上还更差。所以 v1 在目标缺席期间对干扰车的记忆和证据更新，并不是主要伤害。
  - 设计注意：这个拆分并不完全干净。PGIF 证据回滚后，前 8 个 tick 仍由 absent-hold 维持弃权，之后才跟随干扰车。在这段时间里，相机跟着干扰车走，TAH 记忆的位置和速度却停在旧状态，两者不一致。
- 综合判断：在目标缺席期间，问题不在「选哪辆车」,而在「去哪找」:滑行会跟丢，跟随干扰车会锁错。

## 3. 建议

1. **不为「目标不在」输出或部署分布单独重训 TAHRelM。** 预期收益小于上界(+0.12 承诺正确，且不显著),还会改动方法核心、触发 1004 全部臂重跑。
2. 1004 预注册中的「Full 3 种子重训」(方差估计)按原配方执行即可。如果之后要用部署设定 v2 的 DAgger 数据，就作为单独消融，并与 PGIF absent-hold 对照。
3. 下一步的杠杆，按预期收益排序:
   - **目标缺席期间的 WHERE**:预测目标会在哪里重新出现(路网或拦截预测),取代匀速滑行;
   - **跟踪器 ID 稳定性**:v1 臂中目标在相邻可见 tick 间换了 106 次 ID,这会让 PGIF 按 ID 累积的证据失效。

## 4. 补充(同日 FOV 审计后修正结论)

- `runs/data_audit/fov_check_5ep.py` 随机抽了 5 集训练数据(16、22、35、39、55,共 6,354 帧)。确认 `mvp_full_v5`(09-04 重生成版)的**图像和存储的标注框都是 70°**:标注与 FOV70 投影误差 0.0 px,与 FOV90 投影相差 24–40 px(目标)。
- TAHRelM 的离线缓存 `runs/tah_cache.pt`(09-07)是按 `train/config_v5.yaml` 的 90° 投影候选框的。所以 64 集离线数据的外观裁剪和位置特征都取自错位的框，中位偏移约 0.6–1.1 个框宽。只有 23 集 DAgger 数据(闭环 90/90)是对齐的。
- **修正后的结论**:§3 说的「不为加入『目标不在』输出而重训」仍然成立，那属于方法改动，收益上限小。但**按修复 bug 的方式重训**是需要的：结构和配方都不变，只把 mvp_full_v5 的 cache 按 70° 重建，再合并 DAgger 数据。这不算方法改动。替换前先在 dev 上用三项指标验收，并合并进 1004 的 3 种子重训一起做。
- 不受影响的部分:Stage-2(08-17 用原始 90° 数据训练)、闭环评测(相机和投影都是 90°,已目视对齐)、开局属性分类器(训练数据来自闭环快照)。

## 6. 结果(2026-10-04 02:57)与结论

**训练**:3 个种子按验证集选出的 best 都是第 2 个 epoch(val 0.991);第 60 个 epoch 的 val 为 0.986–0.987。离线验证集第 1 个 epoch 就已饱和。

**dev 闭环**(91000–19,最终协议，与 v1 臂 `zoa_*`(旧权重)同种子配对,n = 19):

| 指标 | v1 旧权重 | 新 best(ep2) | 新 last(ep60) |
|---|---|---|---|
| 承诺正确锁定比例 | **0.646** | 0.573(Δ −0.073 [−0.200, +0.052],p = 0.28) | 0.543(Δ −0.103 [−0.204, +0.002],p = 0.07) |
| 最长连续正确(s) | **15.8** | 10.6(Δ −5.2 [−11.7, +0.5],p = 0.13) | 10.2(Δ −5.6 [−11.2, −1.0],p = 0.03) |
| 最长锁错(s) | **8.7** | 15.4(Δ +6.7 [+0.4, +13.6],p = 0.07) | 14.5(Δ +5.8 [−0.5, +12.8],p = 0.12) |
| 严格正确 | **0.719** | 0.616 | 0.606 |

dag_v2 和 dag_old 都是新权重的训练数据，属于样本内结果。

**结论**
- FOV 错位是真实存在的 bug,但对 TAHRelM 几乎没有实际影响：旧权重在对齐后的 90° 数据上同样达到 0.988。TAHRelM 主要依赖相对运动和位置特征;离线评估又是 teacher-forced,本身就容易。
- 修正后重训的两个版本在闭环上都没有提升，4 项指标方向上一致变差，其中部分项接近或达到显著。
- **决定：最终模型继续用旧权重 `runs/tah_relm_dag.pt`。** 新权重保留在 `runs/tah_v90/`,作为负结果存档。
- 注意：同一配置重跑本身有不小的波动(例如 PGIF 0.613 → 0.576)。v1 臂只跑过一次，0.646 可能偏高。如果要更确定，可以对 v1 做一次 A/A 复跑(约 35 分钟)。
- 可能的原因(假设，未验证):
  - DAgger 占梯度步约 69%,且多为短集，带来分布偏移或过拟合;
  - 对齐后外观特征更可信，模型更依赖外观，在 ID 互换或遮挡时反而更脆弱。
- 90° 复刻数据 `mvp_full_v5_fov90` 保留：它和 Stage-2、闭环的 FOV 一致，可供今后的离线工作和跨 FOV 测试使用。
