# 1020 身份压力场景设计稿（P2；讨论稿，未改代码）

2026-10-20。起因：自动优化循环做出 5 次晋升（G3 M1 0.822 → 0.843），创新性评审全部判为 reject。根源在场景：当前分布不需要语言，也不存在真正的 look-alike，循环只能做出外观跟踪类的工程技巧。本稿重新定义研究问题与场景，供拍板。

## 0. 讨论结论（用户 10-20 三个问题）

**Q1 克隆车与语言**
- 同型同色克隆车出现时，语言（"颜色 + 车型"）只在第一帧有用：
  - 时变信息（位置、朝向）随后失效；
  - 时不变信息（外观描述）对克隆车本身就有歧义。
- **采纳**：主实验 **T1 = 首帧给出真值目标框**（SOT/VOT 的标准设定），身份维持环节不读语言。
- 语言保留为第二条件 **T2 = 语言开局（无真值框）**，单独报告"从语言开局"的价值与误差传递。
- 时变/关系型指令（"刚才左转那辆""右车道那辆"）需要情节记忆，难度和工作量更大，列为后续扩展 P3，不进主线。

**Q2 真值世界坐标**
- 合理。属于"特权信息解耦"：去掉深度估计这类非主线任务，聚焦识别、跟踪与跨帧关联。前提是守住三条边界：
  1. 身份决策不读真值坐标（G1 静态检查 + 每局 GT 访问审计，已具备）；
  2. 坐标只喂给 WHERE，且只取当前承诺框对应车辆的坐标，跟错车就飞向错车，真值掩盖不了身份错误；
  3. 补一条鲁棒性轴（§3.4）：框噪声模型与深度噪声，证明结论不依赖完美感知。
- 比坐标更核心的特权，其实是"候选框 = 真值投影"（无漏检、误检、抖动）。这对"识别与跟踪"主线影响更大，必须有鲁棒性实验覆盖。

**Q3 地图（更正事实）**
- 训练数据（`runs/tah_v90/b_manifest.json`，Stage-2 90° 数据）实际覆盖：
  - Town01 ×20、Town02 ×16、Town04 ×11、**Town05 ×11**、Town10HD ×11；
  - DAgger（train_dagger_v1–v3）与开局属性训练集（train_opening 92000–、96000–）都大量使用 Town05。
- **因此 Town05 是见过的地图；唯一完全未见的是 Town03**（`test_town03` 已登记并锁定）。
- 闭环测试按两组报告：**见过的地图**（01 / 02 / 05 / 10HD）与**未见地图**（03）。种子使用新号段，登记前核对与训练种子不重叠。

## 1. 研究问题重述

> **给定首帧目标框，在同型同色克隆车群中，由主动飞行的 UAV 做长时程身份维持与丢失后重捕获。**
> 难点：外观几乎相同（克隆）、跟踪器在交汇和遮挡后换 ID、长时间出画后以新 ID 回来；身份决策直接决定飞向哪辆车（闭环）。

- 这一表述避开了"语言是否必要"的争议。
- 它与 OA-VAT（实例原型抗干扰）、DAM4SAM / KeepTrack（干扰感知记忆）、MOT 的重识别在同一赛道上正面比较，审稿人熟悉，基线明确。
- 新意可以押在：**克隆条件下外观失效，身份只能靠运动连续性、时空约束与闭环主动观测来维持**。这正是现有方法的空白：它们都以外观为主。

## 2. 场景构成

### 2.1 干扰车

| 类型 | 定义 | 每局数量 | 作用 |
|---|---|---|---|
| **克隆 clone** | 与目标同 blueprint、同颜色 | 1–3 | 外观不可分，核心压力 |
| 近克隆 near-clone | 同 blueprint，邻近色（深红/红、银/白） | 0–2 | 外观弱可分，测细粒度外观 |
| 同型异色 | 现有 `same_shape_diff_color` | 0–2 | 保留，可与旧结果衔接 |
| 填充车 | 现有 fillers | 2–4 | 背景 |

- 场景配比（每局抽一种）：clone-heavy（2–3 辆克隆）40%、clone-light（1 辆克隆 + 近克隆）40%、对照（旧分布）20%。对照组用于与旧结果衔接，同时检验方法在易场景上不退化。
- 实现：`scene/language_generator.py` 的 `compose_scene` 新增 `clone` / `near_clone` 策略；`mvp.yaml` 的 `similarity_strategy_weights` 改为新的场景配置 `stress_v1.yaml`。旧场景不改，可复现。

### 2.2 身份压力事件（主动触发，带真值时间戳）

| 事件 | 触发方式 | 考察 |
|---|---|---|
| **E1 交汇/超车** | 克隆车被设为比目标快或慢 3–6 m/s，在 ±10 m 编队带内交错 | 跟踪器换 ID、承诺被错车带走 |
| **E2 长遮挡** | 打开 `occlusion.enabled`，偏向桥下、隧道、高楼遮挡锚点（已有 `occluder_cache`、`occlusion_heavy.yaml`） | 遮挡后以新 ID 回来时的重捕获 |
| **E3 出画再入** | 专家飞行在独立于身份的脚本时段（如第 30–40 s）抬高或偏航，使编队整体出画 6–12 s，再回到编队质心 | 长缺口重捕获（现在基本找不回，0.1–0.25） |
| **E4 分流** | 路口处克隆车与目标走不同路线（TM `set_path`），之后再汇合或保持分离 | 克隆条件下只能靠运动连续性判别 |

- 每局至少一个 E1–E4 事件，记录在 `scenario.json` 中（事件类型、起止 tick、涉及的 actor），用于事件级指标。
- **专家飞行仍然对准编队质心，不对准目标**（现状），避免出现"画面中心即目标"的位置捷径。E3 的出画时段由脚本决定，与身份无关，因此回放依然精确成立。

### 2.3 开局

- **T1（主实验）**：首帧（S2 tick 0）给出目标的真值框，作为**协议输入**而非诊断通道，所有臂相同。复用 `frontend.opening.shared` 机制（`server.py:107-118`，reference actor −1 = 目标）。在新协议里声明为特权输入 `first_frame_target_box`，审计照常进行。
- **T2（语言开局）**：沿用属性开局，`opening.window 3`。
  - 指令去掉"directly ahead / heading east"之类的位置和朝向捷径，只保留"颜色 + 车型"；
  - 位置短语单独作为一组消融。
- 身份维持环节在 T1 和 T2 下都不读语言。

## 3. 协议与指标

### 3.1 新协议 `sim_proxy_v2@4`（不改 @3，旧结果可复现）
- 继承 @3。差异：scenario = `stress_v1`；opening = T1（首帧真值框，作为特权输入声明）；新增事件记录。
- 承诺规则 K = 5 不变（所有方法共享）。

### 3.2 指标
- **主指标**：M1 严格跟随率，同时报告按局平均和按 tick 合并两种口径。
- **事件级指标（新）**：
  - E1 交汇后误切换率（承诺被错车带走的比例）；
  - E2 / E3 / E4 之后的重捕获成功率（目标重现后 6 s 内）；
  - 平均重新承诺时间；
  - 克隆子集上的 M1。
- **安全指标**：M2 误跟率；自飞行下的 TR90 非劣效（δ = 0.02）。
- 置信区间：按种子配对 bootstrap；事件级指标按事件做 bootstrap，并与种子聚类。

### 3.3 立项门槛（第 0 步，参照 1016 的做法；录制完成后先做，不过线就不切换场景）
- 在 G3-tune 上用专家飞行回放：U1x（真值身份）、永不切换、re-ID、**强跟踪器基线**（OC-SORT / ByteTrack 关联 + re-ID 外观）。
- 过线条件：
  1. 提升空间 D = U1x − max(re-ID, 强跟踪器) ≥ 0.15（当前场景只有 0.112）；
  2. 克隆子集上 re-ID 显著低于 U1x，说明外观失效确实发生；
  3. 强跟踪器不能把空间吃掉一半以上。否则说明问题等于"换个跟踪器"，研究价值不足。

### 3.4 鲁棒性轴（论文附录，回应特权感知质疑）
- 框噪声：漏检率 p ∈ {0, 0.1, 0.2}、误检 λ ∈ {0, 0.5}/帧、框中心抖动 σ ∈ {0, 3, 6} px、跟踪器 ID 随机断裂。
- WHERE 深度噪声 ±{0, 10, 20}%。
- 只对最终方法和主要基线跑一遍，不进入优化循环。

## 4. 自动优化循环的改动

1. **G3 分为 tune 与 confirm 两段**：晋升需要同时满足 tune 上 ΔM1 单侧 95% 下界 > 0，以及 confirm 上 ΔM1 ≥ 0（非劣效）。confirm 只返回通过/不通过，不暴露逐种子数据，以阻断"看着种子调阈值"。
2. **时间预算**：tune 120 局约 20 分钟（4 槽；可增至 8 槽，每 GPU 2 个），confirm 80 局约 13 分钟。tune 通过后才跑 confirm，单次晋升总计 ≤ 35 分钟，超出原定 20 分钟上限，需要确认。
3. 实时一致性核对保留，每次抽 4 局，在两段中都抽。
4. 知识库：新增场景事实条目（事件定义、克隆配比、第 0 步结果）；旧场景的晋升标记为"旧场景"。
5. 新开 run（旧 run 保留作为基线历史，不删除）。

## 6. 风险

- **E1 / E4 触发率受 TM 控制精度影响**：冒烟阶段统计触发率；不足时改用 `set_path` 加速度脚本。
- **克隆过多可能让 U1x 本身下降**（真值身份下飞行也会更难），需要在第 0 步一并检查。
- **T1 首帧真值框改变论文定位**：语言从核心贡献降为一个条件，相关工作的切割需要重写（与 OA-VAT / DAM4SAM / 长时 SOT 正面比较）。这是叙事层面的决定。
- **见过的地图上的结果可能偏乐观**：主表必须同时给出 Town03（未见）。

## 7. 拍板结果（10-20 用户）

1. **主实验采用 T1**：首帧真值框为主，语言为条件（T2）。论文定位相应改为"克隆 look-alike 下的身份维持"。
2. 场景按本稿实现；**E4 放第二批**，第一批做 E1–E3。
3. **Town03 只放锁定测试集**，agent 永远看不到（不在 tune / confirm / 审计集里）。
4. 其余各项（G3 两段制约 35 分钟、第 0 步门槛、鲁棒性轴）按本稿默认执行。

### 7.1 实现时新发现：现行 G3 录制中的"专家回中"泄漏（10-20）
- 专家飞行在目标出画后会切到"恢复模式"，直接伺服真值目标，直到目标稳定回到画面 8 帧（`scene_manager.expert_action`）。
- 这意味着重捕获那一刻，画面中心正好是目标。现行 G3 的回放里，"选最靠中心的框"在重捕获时隐含了真值。
- 压力场景的专家改为：E3 出画结束后回到"目标 + 克隆车"的质心，**不进入以目标为准的恢复模式**，目标作为群体中的随机一员重新入画。
- 现行 G3 的晋升结果需注意这一点：重捕获类的收益可能部分来自居中偏置。

**实现中修掉的问题**
- 协议的 `sim.scenario` 原先没有传到 CARLA 客户端（`load_config` 写死 mvp）。
- mvp 的 loss 窗口按 150 s 排程，但一局只有 90 s。
- 专家"恢复模式"在重捕获时把目标居中，相当于泄漏 GT（§7.1）。改为：质心只算目标 25 m 内的相似车，不再走恢复模式。
- 等帧超时由 0.5 s 改为 5 s：同步模式下晚到的帧仍是同一帧，结果不变。
- 专家飞行时跳过 DiT：DiT 输出的动作会被专家覆盖，跳过后每帧从 1.3 s 降到 0.75 s。
- `env.py` 的报错现在包含异常类型和 traceback 尾部。
- 压力场景实验的 `infra.watchdog` 放宽为 first_min 40 / stall_min 25。

**资源隔离**：压力场景的运行只用 CARLA 2090/2230/2250 和策略 GPU 2/5/6，不拿 CARLA 锁；自动优化循环的回放占 GPU 1/3/4/7，实时核对占 2010–2070。
