## ★ 方法学发现(12:10):「正确锁定比例」对弃权的处理不一致,DAM4SAM 的 0.786 主要来自弃权

- **问题**:现用的正确锁定比例 = 1 − `mis_follow_inst`。scorer 只把「选了错车」记为错,弃权帧(`pred_slot = −1`,即没有任何选择)记为**正确**。
  - DAM4SAM 在 SAM2 掩码为空、或预测框 160 px 内没有候选时会弃权。
  - 其余各臂(含 PGIF、V2、V3 系列的融合输出)每帧都会给出选择;V1 / V1-commit-only 的承诺跟随 DAM4SAM,继承了它的弃权(宽松 / 承诺 / 严格 = 0.671 / 0.450 / 0.183 与 0.708 / 0.389 / 0.153)。
  - 另外两项指标(最长连续正确、最长锁错)都按**承诺身份**计算,弃权时沿用上一承诺。三项指标的「锁定」定义因此不一致。
- **证据**(`rollout/iter_gate.py`,用 scorer 的逐帧分桶计数 `n_dist × mis_by_N` 重算严格口径):

| 臂(Town05,n=19) | 宽松(弃权算对,原口径) | 承诺(弃权沿用承诺,与另两项一致) | 严格(弃权算错) |
|---|---|---|---|
| DAM4SAM | 0.786 | 0.367 | 0.190 |
| TAHRelM+PGIF(V0) | 0.583 | 0.576 | 0.584 |
| TAHRelM | 0.326 | 0.320 | 0.326 |
| DeepSORT / OC-SORT | 0.297 / 0.238 | 0.286 / 0.229 | 0.296 / 0.240 |
| DAM4SAM · Town10HD | 0.598 | 0.299 | 0.103 |

  - 除 DAM4SAM 及其 V1 派生臂外,各臂三种口径的差别 ≤ 0.01。DAM4SAM 约 60% 的目标在画面帧处于弃权状态。
  - V0 − DAM4SAM 配对差(n=19):
    - 承诺口径 +0.209 [−0.001, +0.415]
    - 严格口径 +0.394 [+0.167, +0.610]
    - 宽松口径 −0.203 [−0.384, −0.027]
    - 最长连续正确 +8.0 s [−2.4, +18.5]
    - 最长锁错 −11.3 s [−23.3, +0.7]
- **影响**:原定的「正确比例上超过 DAM4SAM」这一目标,是相对一个口径伪影定义的。换成与另两项一致的承诺口径后,V0 在三项指标上方向全部优于 DAM4SAM;严格口径下显著,承诺口径下临界。
- **处理**:
  - **原预注册 endpoint 为宽松口径。** 实验后发现该口径对会弃权的跟踪器不可比,因此把承诺口径作为**修正后的主口径**(用户 22:05 确认)。这一修正发生在看到 DAM4SAM 弃权现象之后,属于结果后修正,如实声明。
  - **预注册是否成功只按原口径判定**:按原口径,1003 的全部预注册假设均未通过,见下方判定表的「宽松」值。
  - 三种口径全部进主表或主文脚注,不只放附录。1001 §5.5 已按此更新(图中 ◇ 标出原口径值)。
  - **口径细节**:`mis_follow_sustained` 在已有承诺之后,弃权沿用上一承诺;episode 开头尚无承诺时的弃权帧不计为错。因此它不完全等价于"弃权一律沿用上一承诺",开头未承诺的帧对所有臂都偏宽。
- **DAM4SAM 弃权诊断(23:45 完成,用户要求;`rollout/dam_diag.py` → `eval_out/dam_diag.json`;dev 91000–19,n = 19,关联门 160 / 240 / 320 px)**:
  - **弃权原因**:目标在候选中的 tick 里,SAM2 空掩码占 64.6% / 64.4% / 51.7%;被关联门挡掉的 ≤ 0.1%。**弃权几乎全部来自 SAM2 自己判定目标消失,与我们的接入方式(掩码 → 框 → 关联门内最近候选)无关。**
  - **更正(10-03)**:「目标在候选中」只按视锥判断,不考虑遮挡。其中一部分空掩码发生在目标被遮挡时,这时 SAM2 判定不可见是正确的。空掩码不等于「目标可见却跟丢」,两者的比例待 G13 的可见性标志量化。
  - **重捕获能力弱**:出现过空掩码的 episode 中,到结束都没再找回目标的有 10/18、10/19、8/18。
  - **给出选择时的准确率**:0.59 / 0.40 / 0.61。
  - **与目标大小无单调关系**:按判丢前的框面积分桶,空掩码率没有一致趋势。
  - **放宽关联门无益**:240 − 160 px 不显著;320 − 160 px 承诺口径 −0.09 [−0.19, −0.01],显著更差。按预注册规则选定 160 px(记入 1004 v4.2)。
  - **同配置复现(160 px 臂 vs 05:06 原运行)**:宽松 0.767 vs 0.786,严格 0.193 vs 0.190,承诺 0.447 vs 0.367(+0.08,n.s.),均复现。**但最长锁错差 −10.6 s [−20.5, −1.4],达到显著。** 这说明长尾指标的运行间方差很大,跨批次比较最长锁错要谨慎;1004 已为此设置 A/A 噪声底线。
- **未解释的残余**:seed 91003 上,4 次独立运行(V0、V1、V3、V3-ens)的首帧语言选择都是 0 号干扰车。DAM4SAM 基线在这个种子上严格口径仍为 0.85,说明它当时的初始化很可能是对的。原因未查明,可能是 DAM4SAM 基线的首个决策 tick 不同,没有 tick 日志无法核对。

### 机理诊断(tick 日志,`iter_mech.py`)
1. **开局身份决定一切(所有臂一致)**:
   - 开局锁对的 episode,承诺正确比例为 0.72–0.99,其中带门控的臂为 0.88–0.99;开局锁错的只有 0–0.17。
   - 各臂开局锁对数都在 7–11/19 之间(**开局准确率**约 37–58%,由首帧语言选择决定)。这和**逐 tick 的语言准确率**(`acc_lang`,全程所有可见 tick 上为 0.22–0.33)是两个量:开局时目标通常靠近画面中心、未被遮挡,所以开局准确率更高。
   - 同一种子的首帧语言选择在多次运行间基本可复现:91003、91006、91007、91008 在 V0、V1、V3、V3-ens 中都错选同一辆车。但也有少数种子翻转(91001、91005),导致臂间开局数相差 ±2–4 集,对应正确比例相差约 ±0.1–0.2。
   - 因此 n=19 的臂间差异有很大一部分是开局这一步的随机性。H3b 的显著负差中,V3 只有 7/19 开局锁对,V0 有 11/19,这一项占了主要部分。
2. **融合闭环中两个记忆的错误高度重合(描述性;不能归因于"回灌"本身)**:

   | 指标 | V3-ensemble | V3-commit-only | V3-gateTAH-only | V3 |
   |---|---|---|---|---|
   | TAHRelM 与 DAM4SAM 的误差相关 ρ_err | **0.34** | 0.67 | 0.72 | 0.72 |
   | 两记忆选同一车的比例 | 0.43 | 0.47 | 0.82 | 0.76 |
   | 两者同时错且错到同一辆车 | 0.22 | 0.18 | 0.37 | 0.48 |
   | DAM4SAM 有选择(未弃权)的 tick 比例 | 0.55 | 0.38 | 0.42 | 0.77 |

   - **能说的**:无回火的逐帧 ensemble 里,两记忆的错误相关较低(0.34,H3c 预测 < 0.5,成立)。一旦进入回火融合闭环,无论是否回灌、回灌几个记忆,错误都高度重合(0.67–0.72)。两个记忆都回灌时,"错到同一辆车"的比例最高(0.48)。
   - **不能说的**:commit-only 不回灌记忆,ρ_err 也有 0.67,所以"回灌导致同步"不成立。更可能的共同原因是融合承诺决定了飞行轨迹,两个记忆看到的是同一段画面。此外各臂的 DAM 出现率(0.38–0.77)、episode 长度和飞行轨迹都不同,ρ_err 不是同一观测分布上的纯机制量。
   - **要主张因果,还需补的分析**:同种子、按开局对/错分层、按 DAM 出现率匹配、逐 episode ρ 的 Fisher-z bootstrap、门控前后窗口对比,最好再加固定轨迹的离线回放对照。
   - **与结果相关的事实**:V3 开局锁对时 0.99,开局锁错时 0.00;ensemble 和 commit-only 开局锁错时还有 0.15,代价是开局锁对时只有 0.72–0.78。V3 的 DAM4SAM 重置中,有 23% 把原本选对的 SAM2 改到了错误身份。双记忆回灌不是净增益,并会在开局锁错时固化错误身份。

3. **V1 退化**:
   - SAM2 预测 IoU 对"DAM4SAM 选对"的 AUROC 只有 0.53,低于预注册阈值 0.55。按预注册说明,PGIF 在 DAM4SAM 上退化为近似等权驻留,540 个 tick 只改写了 24 次。
   - V1 与 DAM4SAM 的差异落在运行间方差之内(V1 − commit-only 不显著)。
4. **V2 无效**:
   - 全程逐 tick 的语言准确率只有约 0.25–0.33,窗口内各 tick 的语言错误很可能高度相关(未单独测量)。累积 5 个 tick 没有提高开局正确率(V2 为 10/19,V0 的首帧语言为 11/19)。
   - V2-single@K 对照未跑,H2a 无法正式检验。

## 总结(诚实结论;按 codex R^b 收窄,`codex/1003_Rb_evidence.md`)
1. **预注册判定**:
   - 按原口径,V1、V2、V3 的全部预注册假设均未通过。
   - V1-selfreset 与 V2-single@K 两个机制对照未跑,对应的机制判定未检验。
2. **修正口径下的 V0 vs DAM4SAM**(结果后分析,非预注册):
   - 三项指标方向都占优,但只有严格口径的正确比例显著(+0.39)。
   - 承诺口径正确比例 +0.21 处于边界;最长连续正确 +8.0 s、最长锁错 −11.3 s 均不显著。
   - 1003 的三个新版本都**没有超过 V0**。V3 在 Town05 上显著更差,其中开局锁对数的差异(7/19 vs 11/19)占了主要部分。
3. **定位**:这批结果应写成"指标修正 + 负结果机理诊断 + 下一步假设生成",**不能**包装成 V1/V2/V3 的方法成功。可进入论文的内容:
   - (a) 评测方法学:会弃权的记忆跟踪器(SAM2 类)在"逐帧错选率"口径下被系统性高估,DAM4SAM 高出约 0.4。
   - (b) 描述性发现:融合闭环中两记忆错误高度重合,双记忆回灌在开局锁错时固化错误身份(因果待补)。
   - (c) 瓶颈定位:开局身份决定了 0.9 以上与接近 0 两种结局;记忆和融合层面的改进,在开局锁错时都无能为力。
   - **单靠这些不够 SCI 一区或 CCF-A 的主线。** 还缺一个正向的方法贡献,或更大规模的证据:更多种子、补齐预注册对照、真实检测/定位噪声、V0 · Town10HD、DAM4SAM 的 tick 日志与弃权原因、固定轨迹的机理验证。
4. **下一步的杠杆是开局身份**:
   - 一是更强的开局 grounding。阶段 0 的 LoRA 未显著有效。
   - 二是开局锁错后的可恢复机制,例如保持来源多样性、只门控承诺的融合。
   - 同时扩种子到 n≈40,压低开局随机性带来的方差。
