## 0. 实验在哪里运行

**全部消融与外部基线都在 CARLA 在线闭环仿真中运行**(Town05 为主，另有 Town03、Town10HD):
- 每个臂驾驶同一架无人机，从同一个种子初始化的场景出发(同一目标、同一组干扰车、同一段 90 帧专家暖场);
- 身份选择决定 WHERE 跟谁，进而改变下一帧画面，所以不同臂看到的后续观测不同;
- 离线回放只用于两类辅助分析：跟踪器 ID 质量(跟踪器只依赖输入，回放精确)与移植基线的一致性核对。

## 1. 原则

1. **只呈现一个最终模型**(hung)。所有消融从它出发，每次只改一个变量;研究过程的中间版本只进附录。
2. **每个论文主张对应一组实验，每组实验有预注册的方向性预测和判定规则**,判定规则在看 test 结果之前冻结。
3. **所有正文数字来自同一份冻结代码、同一个批次、全新的 test 种子**;dev 结果不进正文主表。
4. **部署实验**(自然开局)代表独立部署表现;**机制实验**(共享开局)隔离组件效应，不代表部署表现。
5. **公平性优先**:只对我们有利的设置要么对所有臂对称，要么在正文中披露。
6. **指标度量的必须是无人机实际在做的事**:身份主指标读取 policy 内部用于 WHERE 的承诺，而不是另行滞回后的输出(§4)。

## 3. 冻结的最终模型与评测协议

### 3.1 最终模型(Ours)
- 方法配置 `ours_final`:TAHRelM(`runs/tah_relm_dag.pt`)+ PGIF(tempered + absent-hold),`conf_tau = 0.5`;WHERE 为原规则(承诺 ID 无框时沿用 EAR 航点)。
- 匈牙利跟踪器写入**新协议版本 `sim_proxy_v2@2`**(= `@1` + `perception.tracker.assign: hungarian`),所有实验引用它。
- TAHRelM 训练配方：现有权重没有保存完整配方。T0 中用固定配方重训 3 个训练种子(s0–s2,表 5 需要);若重训 s0 与现有权重在 dev-B 上闭环等价(配对差 95% CI 含 0),论文的 Ours 用重训 s0,否则用现有权重并在附录说明。此决定在 T0 冻结。

### 3.2 闭环设置(协议 `sim_proxy_v2@2`,所有臂相同)
- 相机 512×512、FOV 90°、10 Hz;S2 决策 tick 每 0.6 s(6 帧);集长上限 900 步(90 s);目标连续丢失 18 s 截断;90 帧专家暖场。
- 候选框：任务车辆的真值投影 + 射线遮挡过滤(仿真检测替身);WHERE 用匹配框的真值世界坐标。这两项对所有臂相同，正文局限中披露，并由表 4 的检测 / 关联噪声实验给出边界。
- 属性开局为共享前端(3 个 S2 tick,3× 高清开局帧)。

### 3.4 开局
- **自然开局**(部署表):每个臂运行共享的属性开局，再按统一交接规则(§6 F-c)把开局身份交给自己的身份模块。
- **共享开局**(机制表，回应 R1 M6):
  1. **参考开局**:正式批次第一步，对每个 test 种子用 Ours 跑 19 步的参考开局(`sim_proxy_v2_openval`),在 3 个开局 tick(0 / 6 / 12)分别记录开局累计身份，以场景 actor 编号保存;独立跑两遍，报告一致率。
  2. **开局窗口内统一控制**:机制臂在开局窗口内(第 0–17 步)**不运行各自的身份模块决策**。每个开局 tick 的身份输出、承诺与 WHERE 都强制为参考开局在该 tick 记录的 actor;身份模块状态按统一交接规则用这个 actor 初始化。由于策略随机数也按种子固定(§3.5),各机制臂在开局窗口内的输入、动作与相机轨迹在仿真确定的范围内一致。
  3. **释放**:第 18 步(开局窗口之后的第一个 S2 tick)起，各臂完全按自身机制运行。
  4. **一致性核查**:记录每个机制臂在释放时刻的无人机位姿与候选集合(actor 编号),报告各臂之间的差异;差异来自仿真非确定性，由 A/A 量化(§3.5)。
  5. **fallback 规则(预注册)**:若参考 actor 在某个开局 tick 不在候选中，该种子**从所有机制表中剔除**(所有臂一致),在表注中列出数量与种子号。不做「退回本臂自己的选择」,以免 fallback 成为处理后变量。
  6. 共享开局通过 actor 编号把参考身份映射到当前候选，是一个**对所有机制臂相同的真值通道**,在协议中声明为特权输入(`shared_opening_actor`),只用于机制表。
  7. **参考开局运行属于实验干预，不是开发运行**:它的输出(各开局 tick 的 actor 编号与 fallback 标记)在任何机制臂运行之前固定;不用于模型选择或超参调整;参考开局是否正确只在分析阶段作为分层协变量使用;参考运行本身不产生任何主结果指标。
- **分层变量**:参考开局是否正确(种子级协变量，在任何被比较的臂运行之前确定)。

### 3.5 随机性控制(回应 R1 M8)
- **策略随机数派生规则(预注册)**:每集 reset 时设定
  `torch / numpy / python 随机数种子 = H(场景种子, 重复编号 r, 流编号 stream)`,H 为 SHA-256 截断，**与臂无关**。
  - 同一种子、同一重复编号下，各臂共享同一组策略随机数(共同随机数);
  - 不同重复编号使用不同的盐，重复之间相互独立;
  - stream 区分 EAR 采样、DiT 采样、候选打乱，避免某个臂多调用一次随机数就让后续全部错位。
- **仿真侧**:同步模式;TrafficManager 种子 = H(场景种子, r);每集独立的 TM 端口块。
- **A/A(T0)**:dev-B 上 Ours 跑 2 × 2 组(两个重复编号 × 同一重复编号在两台不同服务器各一次),分别估计「重复间」与「服务器 / 仿真非确定性」两部分方差，用于 §7 的样本量冻结。

### 3.6 调度与基础设施失败(回应 R1 M7、M8)
- **(臂, 重复, 种子块)作业随机打乱**后分配到 CARLA 槽位，调度随机种子写入日志;每集日志记录服务器、GPU、TM 端口、DAM4SAM 服务实例、重试历史。
- 基础设施失败(仿真超时、TM 端口绑定失败、服务崩溃)在其他服务器上用同一种子、同一重复编号补跑，最多 3 次;仍失败的 (种子, 重复) 在**所有臂**中剔除，表注列出。
- 只有 scorer 判为跳过的种子(目标静止)按场景剔除;不因任何结果剔除。

## 4. 指标(回应 R1 M1、M2)

### 4.1 承诺身份的定义
- **policy 承诺**:policy 内部用于 WHERE 的承诺身份(跟踪器 ID),只在 S2 tick 更新;更新条件为置信度 ≥ `conf_tau` 且挑战者连续 K = 5 个 S2 tick(约 3 s),PGIF 改写时直接承诺。这是无人机实际在跟的那辆车。
- **承诺身份 → 场景 actor 的映射**:每个 S2 tick 用该跟踪器 ID 本 tick 匹配到的候选得到 actor 编号;若该 ID 本 tick 没有匹配框，沿用它最近一次匹配到的 actor。scorer 在两个 S2 tick 之间保持上一次的映射。
- **输出身份**(旧口径):每帧的输出选择再经 scorer 的 K = 5 帧滞回(约 0.5 s)。1001 / 1004 中所有已报告的「正确锁定比例」都是这个口径。

### 4.2 指标层次
| 层次 | 指标 | 定义 | 判定用途 |
|---|---|---|---|
| **主指标(身份)** | 承诺正确比例 ↑ | 目标在画面内的帧中,policy 承诺(§4.1)为真目标的帧比例 | 所有预注册假设的判定 |
| **安全指标(任务)** | 固定时域正确跟踪率 TR90 ↑ | policy 承诺为真目标且目标在画面内的帧数 / 900(固定 90 s;截断后的部分记为未跟踪) | **非劣效门槛**:每个确认性比较记为「左 − 右」(左为预测更好的一方);结论「左更好」还需满足 TR90 配对差(左 − 右)的 95% CI 下界 > −δ,δ = 0.02(当前模型 dev 上 TR90 约 0.16,δ 约为其 12%)。适用于表 1、表 2、表 3(a)的全部确认性比较 |
| 次指标(身份) | 最长连续正确、最长锁错(基于 policy 承诺) | 目标出画即断开 | 效应量 + CI |
| 次指标(任务) | SR(τ) 曲线 | 全程无 ≥ τ 秒的 policy 承诺锁错、且未因丢失截断的集比例,τ ∈ {1, 2, 5, 10} s;另报 τ ∈ [0.5, 20] s 的曲线下面积 AUC-SR | 效应量 + CI |
| 对照口径 | 输出身份正确比例(旧口径)、宽松 / 严格口径 | 见 §4.1 | 与 1001 / 1004 衔接;附录 |
| 描述 | 开局锁对率、弃权率(DAM4SAM 等必须在主表报告)、目标在画面内时长、集长、ID 切换次数、重捕获成功率、PGIF 改写率与「缺席」率 | — | 解释机制 |
| 代价(回应 R1 m2) | 三层:①身份模块耗时与显存;② policy 每个 S2 tick 端到端耗时;③整集墙钟时间与 GPU 显存峰值 | 共享前端(Qwen3-VL、DINOv2、DiT)成本单列;外部服务(DAM4SAM、OA-VAT 的 DINOv3)成本单列 | 描述 |

### 4.3 选择理由
- **身份主指标读 policy 承诺**,使它度量「无人机承诺跟随的是不是目标」;在目标出画的帧不计数，因而把身份效应与跟随效应分开。
- **TR90 作为安全指标**:主指标对「更早丢失目标」不敏感(分母只含画面内的帧);TR90 在固定时域上计数，反映身份与跟随的总效果，并对应具身跟踪文献中的 TR。1001 §5.5c 的外推实验说明两类指标可能分离。非劣效门槛(而不只是「不显著变差」)可以防止「身份指标更好、但更早丢失目标」被当作改进,δ 在看 test 结果之前冻结。
- **不用单一 SR 判定**:SR 依赖人为阈值，且成功集少、功效低;改报 SR(τ) 曲线与 AUC。
- **现状**:当前模型 dev 上 TR90 约 0.16,多数集在 90 s 内因丢失被截断，正文同时报告集长。

### 4.4 实现(T0 必做)
- scorer 新增 policy 承诺的逐帧统计(policy 在 ActInfo 中返回承诺的跟踪器 ID 与映射到的 actor);在 episode 汇总中写出主指标、TR90、SR(τ)、AUC-SR 与旧口径;
- 分析脚本 `acot/analysis/metrics.py` 增加这些指标;
- 单元测试 + golden 示例:手工构造的帧序列(含 PGIF 直接承诺、滞回切换、目标出画、截断)对应的期望值。

## 7. 样本量、重复与功效(回应 R1 M5)

### 7.1 依据

|---|---|---|---|---|---|
| 表 1 族 A | 2 | 0.025 | 80 | 0.13 | 0.11 |
| 表 1 族 B | 7 | 0.0071 | 80 | 0.15 | 0.13 |
| 表 2 | 5 | 0.010 | 80 | 0.14 | 0.12 |
| 表 3(a) | 3 | 0.0167 | 80(两图合并) | 0.14 | 0.12 |

- 若共同随机数 + 共享开局把机制表的配对差 SD 降到 0.25,表 2 的 MDE 约 0.10(2 次重复;0.25 / √80 × 3.42 = 0.096)。
- 已知效应：属性开局 +0.21;匈牙利 +0.12;外部基线在旧协议下与 Ours 相差 0.2 以上;**PGIF 在 v2 下约 +0.09,低于上表多数格**。

### 7.3 重复次数的冻结规则(保守方差;T0 之后、启动 test 之前)
A/A 只估计同一臂重跑的技术噪声(重复间、服务器间),**不能**估计臂与臂之间按种子变化的处理效应异质性，所以不单独用于决定样本量。冻结规则:
1. **dev-B A/B 预实验(T0)**:在 dev-B 40 个种子上，用新口径主指标跑三组配对，每臂 r = 2:
   - 部署：Ours vs w/o PGIF、Ours vs w/o 属性开局(自然开局);
   - 机制:Full vs w/o PGIF(共享开局)。
   预实验不用于任何调参或主张，只用于方差估计。
2. **记号与估计式**(每类实验分别计算，主指标为新口径):
   - V₂:dev-B 预实验中，每个种子对 2 次重复取均值后的配对差(左 − 右)的样本方差，取其 80% 单侧置信上界(卡方区间);
   - V_run:单次运行时配对差中的运行噪声方差。由 A/A 估计：同一臂、同一种子两次独立运行之差的样本方差即为 2σ²_run,而两个臂各运行一次时配对差中的运行噪声为 2σ²_run,所以 V_run = A/A 两次运行之差的样本方差;取其 80% 单侧置信**下界**(使外推保守);
   - 外推到 r 次重复:V(r) = V₂ − V_run / 2 + V_run / r。r = 2 时 V(2) = V₂;r > 2 时只扣除已被 A/A 下界确认的运行噪声部分;
   - ρ = V_run / 0.38²(运行噪声占历史 A/B 配对方差的比例，上限截断为 1)。
   **冻结用的配对差 SD** 取下列三者中的最大值:
   - (a)√V(r);
   - (b)历史 A/B 下限:0.38 × √(1 − ρ + ρ / r)(§7.1 的 0.38 为单次运行、旧口径);
   - (c)A/A 技术噪声 √(V_run / r)(只作下限)。
3. 选择最小的 r ∈ {2, 3, 4},使表 1 族 A 与表 2 的 MDE(用上述冻结 SD、各族最严一步 α、功效 0.8)≤ 0.10;
4. 若 r = 4 仍达不到，按 §7.4 预先降级;
5. r、n、冻结 SD 及其来源写入本文件附录并冻结;此后不做中途查看后的增减。
- 分析时每个种子对 r 次重复取均值，以种子为配对单元;另报以重复为随机效应的混合模型作为敏感性分析。

### 7.4 降级规则(预注册)
