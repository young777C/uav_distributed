## 1. 诊断：re-ID 比 Ours 好在哪里(只用 dev-B 已有闭环日志)

脚本:`runs/id_iter/diag_events.py`、`runs/id_iter/diag_switch.py`(结果 `diag_*.json`),S2 tick(0.6 s)粒度。

### 1.1 先弄清指标口径

`acot_client/scoring.py`:承诺的跟踪器 ID 在本帧没有框时，沿用它**最后一次匹配到的车**。因此目标换了新 ID 后，只要承诺仍停在目标的旧 ID 上，就算「正确」(此时 WHERE 没有框可飞，由 EAR 航点驱动)。所有组口径相同;但要知道：**指标不要求重捕获新 ID,只惩罚承诺切到干扰车**。论文里要写明这一点。

### 1.2 丢失与恢复(按指标口径)

| 组 | 可见 tick 正确 | 每局「目标→干扰车」切换 | 至少丢过一次的局 | **首次丢失后的正确率** | 首次丢失后的 tick 占比 |
|---|---|---|---|---|---|
| Ours r0 / r1 | 0.60 / 0.55 | 1.2 / 1.2 | 0.70 / 0.75 | **0.21 / 0.21** | 0.42 / 0.47 |
| re-ID | 0.74 | 1.6 | 0.80 | **0.56** | 0.47 |
| xattn | 0.64 | 1.1 | 0.75 | 0.17 | 0.39 |
| DeepSORT 式 | 0.61 | 1.1 | 0.72 | 0.25 | 0.37 |
| OA-VAT | 0.66 | 1.2 | 0.70 | 0.28 | 0.43 |
| DAM4SAM-L r0 / r1 | 0.82 / 0.72 | 1.1 / 1.1 | 0.60 / 0.62 | 0.65 / 0.34 | 0.41 / 0.35 |

- 开局都对(约 0.95);目标在画面里时被干扰车抢走的情况几乎没有(每局 0–0.07 次)。**所有切换都发生在目标出画 / 被遮挡,或目标换了新跟踪器 ID 的时候**。
- **re-ID 并不比 Ours 丢得少(反而略多),它赢在丢了以后能找回来**:首次丢失后正确率 0.56 对 0.21。首次丢失后的时段占可见时间的 40–47%,所以这一项基本决定了差距。

### 1.2b 更正(同日核对):大部分「丢失」是跟踪器 ID 互换，不是身份模块改承诺

「首次丢失后的正确率」= 每局第一次「承诺对应的车从目标变成干扰车」之后，目标可见的 S2 tick 中承诺对应目标的比例(只统计丢失过的局，tick 合并;非配对，只作描述)。把丢失按成因拆开(`runs/id_iter/loss_kind.py`):

| 组 | 跟踪器把承诺的 ID 换给了别的车(承诺 ID 未变) | 身份模块把承诺改到干扰车 |
|---|---|---|
| Ours r0 | 1.00 次/局，找回 0.53(中位 4.2 s) | 0.23 次/局，找回 0.11 |
| Ours r1 | 0.80 次/局，找回 0.50(中位 2.1 s) | 0.42 次/局，找回 0.35 |
| re-ID | 1.23 次/局，**找回 0.67(中位 0.6 s)** | 0.38 次/局，找回 0.13 |
| xattn / OA-VAT / DeepSORT | 0.78 / 0.95 / 0.68 次/局，找回 0.47–0.52 | 0.23–0.42 次/局，找回 0.08–0.44 |

- 65–80% 的丢失是**共享跟踪器的 ID 互换**;re-ID 的优势集中在这一类(找回更多、更快)。身份模块自己改错承诺的那一类，各方法都很少找回。
- K = 5 滞回下策略无法在 1 个 tick 内改回承诺，所以 0.6 s 的找回多半是跟踪器把 ID 换回来;为什么 re-ID 的局里换回更多(相机运动?)待查。
- **因此 1.3 的「根因 = TAH 记忆被错误承诺写坏」未被证实**,1.3 只描述现象。可能的杠杆改为:**尽快发现承诺的 ID 已被换给别的车，并改承诺到真目标**(承诺 ID 校验),而不一定是「保护记忆」。§2 方案需按此修订后再讨论。

### 1.3 Ours 丢失后为什么找不回来(现象描述;根因见 1.2b 的更正)

首次丢失后、目标可见的 tick:

| 组 | 头的原始选择 = 目标 | 过 PGIF 后 = 目标 | 承诺 = 目标 | PGIF 处于「缺席」 |
|---|---|---|---|---|
| Ours r0 / r1 | 0.30 / 0.28 | 0.24 / 0.19 | 0.22 / 0.21 | 0.15 / 0.24 |
| re-ID | **0.52** | 0.52 | 0.56 | — |

1. **TAHRelM 的循环记忆在跟错后被错车覆盖(自确认)**:丢失后头本身只有约 0.29 选中目标。默认写入的是自己的选择;承诺又让相机跟着错车，错车的视图不断写进记忆。
2. **PGIF 进一步挡住恢复**:目标明明可见，却有 15–24% 的 tick 处于「缺席」状态(按旧跟踪器 ID 记账，见 1007 §4c #3),本 tick 不出选择，挑战者计数无法累积。
3. re-ID 的 K = 2 多样性 gallery 更新很慢(相似度 ≥ 0.9 的视图不存),目标的旧视图能留很久，跟错以后头仍有一半时间选中目标，K = 5 滞回就能把承诺切回来。

### 1.4 两个被否定的方向

- **冻结开局外观做锚点重锚**(9 月 e18e427 的 `reanchor=anchor`,从未评测):在 @3 on-policy 数据(`tah_dagger_v3`,117 局)上，开局 3 个目标视图组成的锚点，在目标可见时认对的概率只有 0.46,开局 10 帧后降到 0.37–0.42;目标与锚点的相似度中位数从 0.72 掉到 0.42,干扰车常常更像。而且目标缺席时锚点的最佳匹配必然是干扰车，旧实现会误触发。**单独用冻结外观做重捕获不可行**。
- **开局属性模块直接用于重捕获**:开局锁对 0.95 依赖 3× 高分辨率帧，而高分辨率相机只在开局几个 tick 存在(`env.py:98`)。512² 下的判别力未测，按「分辨率墙」记忆会明显下降;若要用，需要协议改动(按需高分辨率裁剪)。暂不作为第一选择。

## 2. 方案(10-18 修订稿，待讨论;10-16 原稿存于 `runs/id_iter/1016_sec2_3_v0.md`)

> 修订原因:(1)§1.2b 已更正根因：大部分丢失是共享跟踪器把承诺的 ID 换给了别的车，原稿缺少针对它的一项;(2)§4.6–4.8 的新结果要回填，迭代目标随之改变;(3)§3 缺少「先测上限」这一前置判定。

### 2.1 目标改为超过「永不切换」

- 「开局后永不切换」零假设:dev-B @3 承诺正确 0.660、TR90 0.185(§4.6–4.7,12 组原版 MOT 合并估计)。它高于 re-ID 0.636,也高于 Ours 0.525。**新目标：在 test 上显著超过永不切换，同时不低于 re-ID。**
- 在现行指标下，「保持不动」几乎没有代价：承诺 ID 没有框时沿用它最后匹配到的车，目标不在时停在目标的旧 ID 上也算对(§1.1)。代价只出在两处：
  1. 承诺的 ID 被跟踪器换到干扰车上;
  2. 身份模块主动把承诺改错。
- 收益只能来自:**目标带着新 ID 回来时，比永不切换更快、更准地把承诺移过去**。
- 由此得到设计原则：**切换必须在证据很强时才做，期望收益为正;怀疑承诺 ID 已被换走时，宁可撤销承诺，也不要跟着错车走。** 撤销在承诺正确上不增不减(错 → 无承诺，都记为不正确),但 WHERE 不再飞向错车。

### 2.2 根因(按 §1.2b 更正后)

| 丢失方式 | Ours r0 / r1 | re-ID | 说明 |
|---|---|---|---|
| 跟踪器把承诺的 ID 换给别的车(承诺 ID 未变) | 1.00 / 0.80 次/局;找回 0.53 / 0.50,中位 4.2 / 2.1 s | 1.23 次/局;找回 0.67,中位 0.6 s | **占全部丢失的 65–80%**;0.6 s 内的找回多半是跟踪器自己把 ID 换回来(K = 5 滞回下策略改承诺至少 3 s) |
| 身份模块把承诺改到干扰车 | 0.23 / 0.42 次/局;找回 0.11 / 0.35 | 0.38 次/局;找回 0.13 | 各方法都很少找回 |

阻碍恢复的两个现象(§1.3,因果作用只有第 2 条有闭环证据):
1. TAH 记忆在跟错后写入错车(丢失后头的原始选择只有 0.29 指向目标，re-ID 0.52;论文 2 S0:目标不在时 margin 反而更大，AUROC 0.326)。
2. PGIF 缺席判定：丢失后 15–24% 的可见 tick 被判缺席，挑战者计数无法累积。共享开局下去掉 PGIF,承诺正确 0.585 / 0.589 → 0.698 / 0.677,6 s 内真实再捕获 0.79(§4.7、§4.8);但自然开局下去掉 PGIF 反而更差(0.30–0.42),推断它的作用集中在开局阶段。

### 2.3 新证据(§4.8 再捕获统计，描述性)

- 缺口前在跟目标、目标回来后 6 s 内真实再捕获(承诺 ID 落在目标框上):Ours 0.60 / 0.62,永不切换 0.65,re-ID 0.82,w/o PGIF 共享开局 0.79。
- 同种子配对:Ours − re-ID −0.26 [−0.48, −0.05](p = 0.033);Ours − 永不切换 −0.04(n.s.)。
- 再捕获大多发生在目标回来的当 tick(跟踪器还了旧 ID),身份模块在随后 6 s 内额外找回的只有 +0.04–0.15。
- ≥ 6 s 的长缺口几乎都找不回(0.1–0.25)。
- **对设计的含义**:re-ID 的再捕获高于永不切换，承诺正确却不高于它 → re-ID 的切换里有相当一部分切错了。新设计要同时做到「回来时找得回」(像 re-ID)和「不乱切」(像永不切换)。

### 2.4 修订后的候选

都在 acot 运行时，用方法级开关控制，缺省 = 现行为。身份决策只读图像框、裁剪特征和自身相机位姿，**不读 `world_xyz` / `depth_m`(真值)**。

| 编号 | 改动 | 针对 | 依据 |
|---|---|---|---|
| V1 | TAH 记忆只写承诺身份(已有开关 `identity.tah.memory_write: committed`);有 V3 时再加条件：本 tick 通过校验才写 | 记忆被错车写入 | 单次 0.580(+0.055,n.s.),未重复 |
| V2 | 受保护 gallery 融合:z = TAH logits + λ · gallery 分数;gallery 在开局窗口播种，之后只在「承诺身份 + 置信 + 通过校验」时写入，慢更新、保留多样视图(同 re-ID 的 K-view 规则) | 丢失后缺少不被污染的外观记忆 | 离线 +0.03–0.06;re-ID 的恢复来自慢更新 gallery |
| **V3(新增)** | **承诺 ID 校验**:承诺 ID 本 tick 有框时，比较该框的裁剪特征与受保护 gallery 的相似度，并检查图像系位置 / 尺寸相对上一次可信观测的跳变(用自身位姿补偿相机运动)。不一致连续 c 个 tick → 判定 ID 被换走：停止写入记忆，撤销承诺(WHERE 回到 EAR 航点),进入搜索状态 | **占 65–80% 的跟踪器 ID 互换** | §1.2b;撤销不改变承诺正确，只停止跟错车 |
| V4(原 V3) | 恢复通路：融合选择与承诺不一致(或处于搜索状态),且 gallery 分数领先 ≥ m 连续 N tick(N < 5)→ 直接改承诺，并用该候选重置 TAH 记忆 | 回来后找回太慢(K = 5 需要 3 s) | §1.3 第 1 点;§4.8 回来后 6 s 内额外找回只有 +0.04–0.15 |
| V5(原 V4) | PGIF 缺席判定只在承诺 ID 无框时生效，开局窗口内保持现行为 | PGIF 挡住恢复 | 共享开局下去掉 PGIF:+0.10 承诺正确，再捕获 0.79;自然开局下整体去掉更差 → 只限制作用范围，不整体去掉 |

- **原稿 V1–V4 是逐级叠加;修订稿改为可组合的开关**,便于按证据强弱拆开筛选(§3 第 3 步)。
- **诚实框定**(沿用原稿并补充):V2 起，我们的身份头 = TAHRelM(短期关联)+ 受保护外观记忆(长期恢复)+ ID 校验 + PGIF。必须报告的消融：
  - 只有 gallery(≈ re-ID)、只有 TAH、两者融合;
  - 把 V3 + V4 接到 re-ID 上。若 re-ID + V3 + V4 ≥ 我们，说明贡献只在校验与恢复通路，不在 TAH。
- **调参纪律**:λ、m、N、c 与校验阈值都不在 dev-B 上调。
  - λ 在 dagger v3 / v3_val 上定。
  - V3 的阈值需要带跟踪器 ID 的日志，但 dagger v3 只存了 actor 编号(`aidx`),没有跟踪器 ID。两个办法：
    - (a)离线在 dagger v3 上重放共享跟踪器，得到 ID(要先核实存下的 `pos` / `feat` 是否足够);
    - (b)新开一组调参种子(不与 dev-B / test 重叠),打开 `trk` 记录，用现行 Ours 采集。

## 4. DeepSORT / OC-SORT 原版复现(外部基线，2026-10-16 用户要求)

用户要求：DeepSORT、OC-SORT 都有论文和开源代码，直接复现作为外部基线，替换原来自实现的「DeepSORT 式 / OC-SORT 式」(后者只是 160 px 运动门 + 外观滑动平均的单目标关联器，不是原算法)。

### 4.1 来源

| | 论文 | 仓库(克隆到 `external/`,固定 commit) | 许可 |
|---|---|---|---|
| DeepSORT | Wojke, Bewley & Paulus, ICIP 2017 | `nwojke/deep_sort` @ f08cf1d | GPL-3.0(公开代码时需单独处理) |
| OC-SORT | Cao, Pang, Weng, Khirodkar & Kitani, CVPR 2023 | `noahcao/OC_SORT` @ 8462e7e | MIT |

### 4.2 接入方式(`acot/runtime/head_mot.py`,按 1006 §5.6 的移植原则)

- **原代码直接导入，不复制、不修改**:DeepSORT 的 `Tracker`(卡尔曼 + 马氏门 + 外观级联匹配 + IoU 补充匹配 + n_init / max_age),OC-SORT 的 `OCSort`(卡尔曼 + ORU / OCM / OCR,纯 IoU 关联)。只读回「本步每个框关联到哪条轨迹」:DeepSORT 用子类记录 `_match` / `_initiate_track` 的结果;OC-SORT 在私有模块副本里把 `KalmanBoxTracker` 换成只做记录的子类，记下每次新建 / 更新收到的检测行(`dets[i, :]` 视图)，按视图在数组里的行偏移得到框的下标，并核对数值与输入行一致。依赖 scipy、filterpy 放在隔离目录(`runs/pydeps_oavat`、`runs/pydeps_mot`),追加到 sys.path 末尾，不覆盖镜像里的包。
- **单目标用法**:跟踪器跑全部共享候选框;开局把目标绑定到开局选择所在的轨迹(每个开局 tick 重新绑定，1006 F-c);之后每个 S2 tick 的选择 = 这条轨迹本步关联到的框，没关联到就弃权(承诺不变);轨迹被删除后本局一直弃权(原系统除跟踪器自身关联外没有重识别)。
- **替换项(对所有臂相同)**:检测器 → 协议的共享候选框(置信度 1.0);DeepSORT 的外观网络(MARS 行人 re-ID,128 维)→ 共享的裁剪 DINOv2(384 维)。
- **帧率(用户 10-16 决定：两种都跑，10 Hz 进主表)**:
  - 主表 `ext_deepsort` / `ext_ocsort`:跟踪器每个相机帧(10 Hz)走一步;两个 S2 tick 之间的帧由服务端 `SimProxyPerception.frame_detections` 按与 S2 tick 相同的投影、框大小和遮挡规则给出候选框(不更新共享跟踪器，用独立随机流打乱顺序,S2 tick 的随机流和候选顺序不受影响);身份决策仍每 0.6 s 一次。这两个基线因此看到的帧数是其他方法的 6 倍，这种不对称对我们的结论是保守的，正文要写明。
  - 附录 `ext_deepsort_s2` / `ext_ocsort_s2`:每个 S2 tick 走一步(协议原样)。
- **单位换算**:原默认值按 MOT17 的 30 fps 换算成时间，再换到步长;证据计数不换。max_age 30 帧 = 1.0 s → 10 帧(10 Hz)/ 2 tick(0.6 s);delta_t 3 帧 = 0.1 s → 1 步;n_init、min_hits 保持 3。min_hits 只控制 OC-SORT 的对外输出，本适配读的是内部关联，不受它影响。
- 头的置信度 margin 只有 1(有选择)或 0(弃权),conf_tau 不起作用，不纳入网格。

- 40 局里**每一局**绑定的目标轨迹都被删除(10 Hz 中位数约 6 s,0.6 s 约 1–2 s):目标被遮挡或出画超过 max_age 后轨迹删除，重新出现时位置已移动，IoU 关联不上，只能新建轨迹。

1. 「粘住开局 ID」在 dev-B 上的承诺正确约 0.66(TR90 约 0.185),与最好的身份模块 re-ID 持平或略高，明显高于 Ours(0.525)。即**目前所有身份模块(包括 Ours)都没有超过「永不切换」**;身份模块的主动切换整体上是净损失。这与 §1.2b(大部分丢失是共享跟踪器的 ID 互换)和记忆中的 Sticky-ID 零假设一致，也与指标口径有关(§1.1:承诺 ID 无框时沿用最后匹配的车，指标不要求重捕获)。
2. 迭代目标应改为**超过「粘住开局 ID」这一零假设**,而不只是超过 re-ID。论文里也必须报告这个零假设。
3. DeepSORT / OC-SORT identity adaptation 在本任务里退化为该零假设;正文若保留，需写明「目标轨迹在所有局中都会被删除，之后等价于不切换」,不能写成它们的身份机制胜过我们。

### 4.8 WHERE 的位置来源与「目标不可见后再捕获」统计(10-18,用户提问)

**WHERE 用的是真值位置**(`acot/runtime/policy.py:_where` 425–444,`perception.py:process` 80–89):身份由模型决定(跟哪个跟踪器 ID),位置由真值给。承诺 ID 本 tick 有框时，取该框对应车辆的**真值世界坐标**(目标 = `tpos`,干扰车 = `dstates`;承诺到干扰车就拿干扰车的真值)喂匀速估计器，生成航点覆盖 EAR 航点→DiT;无框(遮挡 / 出画 / 换了新 ID)时保留 EAR 采样的航点(模型预测，`absent_where: cv` 时改为对上次真值位置做匀速外推)。候选框本身也是真值投影的伪框。所有臂相同。完整系统对比前须换成不依赖真值的定位(1009 §5)。

**再捕获统计**(`runs/id_iter/recapture.py` → `recapture.json` / `.log`;S2 tick 粒度，描述性、非配对)。
- 已有字段 `episode.json: reacquire_*` 是旧口径(只把出画算丢失;按记分器自己的逐帧 5 帧滞回判对，不是策略承诺),不用。
