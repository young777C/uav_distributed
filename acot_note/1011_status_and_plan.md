## 1. 已确立的发现

### 1.1 任务与语言(H0)
- 四轴交集(空中主动飞行 × 语言指定车辆 × 相似车消歧 × 具身闭环)无先例;novelty 押"耦合",不写"首个"。ACoT 机制迁移自 ACoT-VLA,诚实定位。(memory: positioning / relwork-cuts)
- 语言首次干净地 load-bearing 需要四个条件:几何捷径除净、指标诚实、稳定训练、分辨率足够。**最深的墙是分辨率**:336→512 px,车 12→27 px,有/无语言错跟 58% vs 72%,差约 13 pp。(memory: language-necessity)

### 1.2 瓶颈在 WHICH(认哪辆车),不在 WHERE(飞到哪)
- 4 臂 WHERE 阶梯:便宜的匀速先验已把 WHERE 补上(跟踪时长 24→65 s),但 SR 始终为 0,重捕获锁错率约 0.74 在各臂持平 → **给出完美位置也会认错车**。(memory: reid-reframe)
- 控制侧修取景两次被证伪(BC-居中、Stage-3 RL):居中在身份下游,会放大认错带来的甩头。**控制不是杠杆,身份才是。**(memory: stage3-rl)

### 1.3 身份:可部署的身份信号是真正的缺口
- re-ID 阶梯 0.31→0.72(正确跟踪帧占比),但 gallery 每帧由真值目标播种 → 换成可部署的承诺播种后只有 **0.363**。
- 语言兜底重锚(单帧 0.225、时序 0.291)均低于无重锚基线 0.363 → **语言不能当身份仲裁**,只做初始指定。
- **oracle 重锚 0.741** 定义了"可部署、抗漂移身份信号"的上界缺口。(memory: reanchor-result)

### 1.4 评测协议与度量
- latch-SR 饱和、无分辨力 → 主指标改为连续客观量;10-06 起主指标读 **policy 内部承诺**(旧 scorer 口径不同)。永远同种子配对。(memory: rigor / cvpr-exp-design)
- **Sticky-ID 零假设**:仿真器的持久 actor 编号让"出画后重捕获"在身份层被白送;"首次选中永不切换"≈ PGIF → 必须用会断开的真实跟踪器 ID,Sticky-ID 必须进表 1。(memory: sticky-id-null)
- 跟踪器此前一直是贪心匹配 → 改匈牙利,承诺正确 +0.085(p=0.02)。(memory: tracker-hungarian)
- 协议 @3 = @2 + 环境确定性(同步 setup + 每集 reload_world),交通逐位一致。

### 1.5 数据与身份模型的消融(10-03/04)
- 全车标注约 20× 事件,但在 v5 上对身份模块无净收益;部署瓶颈变为"弃权锁死"(判"不在"→不写记忆→更判不在)。(memory: event-centric-data)
- 世界系运动在 3% 逐帧深度误差下崩溃,输给图像系 → 若主张世界系运动,必须报估计坐标鲁棒性。(memory: world-coord-fragility)

### 1.6 新协议闭环结果(10-08,dev-B 93060–93099,n=39,自然开局)

### 1.7 实时性 / 端侧(10-08 预评估,未在端侧实测)
- 按现在的实现,任何方法都不能在端侧实时:瓶颈是共享栈(DiT 每帧 282 ms,A40 上已是 10 Hz 预算的约 3 倍)。
- 身份模块专属开销:Ours / re-ID / 关联类 < 20 ms(端侧);DAM4SAM 每 tick 约 274 ms(为 Ours 1.5 ms 的约 180 倍)→ 可形成"精度–算力"权衡论点。(`1007` §5.8)

### 1.8 训练数据(10-09 → 10-11)
- 原 `mvp_full_v5_fov90` 目标静止帧 62%。根因:`restore_target_speed` 用 9 km/h(单位错误,目标全程 2.5 m/s)+ 背景车聚集排队。另:09-04 重生成的 70° 数据被按 90° 投影使用 → TAHRelM 全线、BC 居中、Qwen LoRA 存在投影错位。(memory: data-fov-mismatch)
- 新数据集 **`/nvidia/hque/data/carla_data/mvp_v5_fov90_fast`**(64 集,96k 帧,512²,FOV 90°,城镇分布同原 v5):
  - 运动学:目标 / 干扰车 10–12 m/s,无人机水平严格限 15 m/s(kp 0.9–1.2);防卡死(强制变道 → 挪走前车 / 背景车,含红灯排队识别);卡死 40 s 截断。codex 三轮通过。
  - 生成中发现并修复两类缺陷:① 背景车泄漏(新进程连同步模式服务器、未 tick 前读不到 actor → 清场失效,同城镇连续集逐集累积静止车;修复后通过率 10% → 85%);② 无人机穿楼(无碰撞运动学模型,楼内帧 0.77% → 3 集严重的已替换)。
  - **QC v3** 全部通过:未截断、无 ≥40 s 静止、运动帧 ≥ 35%、楼内帧 ≤ 5%。运动帧均值 0.58(原约 0.38)。
  - 训练时必须打开 `data.frame_mask: train`(屏蔽画面内挪车与楼内帧,各 ±1 s,共 1.35% 帧)。清单 `manifest.json`。
  - 记录:`memory acot-uav-datagen-moving-1009`、`runs/datagen_moving/`(编排器 `full_fast.py`、`qc.py`、`building_check.py`、`kin_patch/` 内全部 codex 记录)。

**身份头特化部分(方法间唯一的差异)**

| 方法 | 身份头 | 额外推理参数 | 训练 | 合计 |
|---|---|---|---|---|

- **推理时 Qwen 没有被截断**:`acot_probe/backbones.py:158` 调 `self.model(**inputs, output_hidden_states=True)` 跑完 36 层,只取第 24 层隐状态(`OnlineVLM.layer=24`),第 25–36 层的计算对输出无贡献。截断可省约三分之一的 LLM 计算(按层数粗算,未实测),会改善 §1.7 的端侧时延估计。
- DAM4SAM 的 SAM2 在独立进程 / 容器里,不占 policy 进程显存,但推理成本真实存在(约 274 ms/tick,见 §1.7)。
- DAM4SAM 的模型档位为 `sam21pp-L`(由运行中的 4 个服务进程命令行核实,`infra/default.yaml` 的 `{model}` 只是占位符);S / T / B+ 在我们的闭环里**没有任何评测**,不知精度掉多少。

## 2. 论文定位:需要拍板的核心问题

当前证据支持:**任务 + benchmark + 诊断(WHICH 是墙)+ 负结果链 + 评测协议(Sticky-ID、承诺口径、连续度量)**。不支持:**"我们的身份模块优于现有方法"**。

可选路线:
1. **方法路线**:用新干净数据 + 新协议重训身份模块(TAHRelM / DAgger),并落实 §4c 剩余改进,争取在 test 上追平或超过 re-ID / OA-VAT;DAM4SAM 用"精度–算力"权衡对待。风险:4 周内能否出正向结果。
2. **诊断 + benchmark 路线**:主贡献改为任务 / benchmark / 协议 / 诊断 / 负结果,我们的系统作为强基线之一;对 CVPR novelty 审稿人偏弱,退路 CoRL / NeurIPS D&B。
3. **主动跟踪路线**(10-08/09 讨论):研究定位为主动跟踪(WHERE + WHICH + HOW),OA-VAT 为关键基线,ReferTrack 微调作为开源主动跟踪 VLA 基线。
