切成训练样本(滑动窗口)

→ 8447 train · 1200 val
  • 砍掉每段尾部 60 帧(horizon = max_horizon 6s × 10fps),保证最远 waypoint(i+60)存在 → valid = n − 60
  • 取窗口起点 i = 0, 3, 6, …(stride 3),每段封顶 200 个样本
  • 每段产出 min(⌈(n−60)/3⌉, 200) —— 实测每段 min 11 / 中位 200 / max 200
  • 每个样本 = 单帧锚点 i + 一个难度标签 a/b/c(按该帧有无相似干扰车)
train 池的 tier 原始分布(共 8447)数据本身已偏难(c 占 63%)
a 800 · 无干扰b 2300 · 同类c 5347 · 近同款,需语言
3

预计算:冻结 Qwen3-VL-4B 前向(离线)

★ 关键变换
把每个样本的单帧 RGB + 语言 prompt 送进冻结的 Qwen3-VL-4B 跑一次,抽出中间层 token 存盘。
RGB 336×336 + 语言 prompt ──冻结 Qwen3-VL──▶ vlm_ctx_layers (5, 100, 2560)
  • 抽 5 个层:第 4 / 8 / 12 / 16 / 24 层(供 IAR 逐层查询)
  • 100 个 token = 10×10 空间网格;2560 = 隐藏维(Qwen3-VL-4B)
  • 存 runs/ctx_cache_ml/*.npz ≈ 27 GB,60 shard,6 卡并行抽取
为什么离线跑一次: VLM 是冻结的,对同一帧输出恒定 → 没必要每轮重算。 预计算:每帧 1 次前向;若训练时在线跑 = 8447 样本 × 50 epoch = 约 42 万次。 这也是「多卡预计算 → 单卡训练」成立的原因,以及换 backbone/分辨率必须重建缓存的原因。

≈ 129 万 float3299.4% 是冻结 VLM 编码

监督目标 · 仅 ≈ 96 个数

action (16,5) = 80 Δ动作×16 + search_mode
waypoint (4,3) = 12 相机系 1/2/4/6s
target_idx · occ_struct · maneuver · visible = 4
形态:重感知 → 轻动作。巨大的一帧感知输入,只对应一小段动作 + 少量标签。
注意「数值量 ≠ 真实信息量」: 那 129 万个 float 是同一张单帧 + 语言的冗余再表示,内在信息 ≈「一帧场景 + 目标此刻姿态」——其中缺"目标速率",正是远期 waypoint 欠定、误差随 horizon 增长的根因。
