## 1. 出发点(数字均为 dev-B @3,n = 40)

| | M1 | 承诺正确 | TR90 |
|---|---|---|---|
| 上限 U1(身份完美) | 0.822 | 0.754 | 0.230 |
| 永不切换 | 0.685 | 0.665 | 0.179 |
| re-ID | 0.684 | 0.636 | 0.193 |
| **基准 Ours-CV** | **0.531** | 0.501 | **0.199** |

- **差距**:Ours-CV 比永不切换低约 0.15(M1),离上限差约 0.29。**第一目标是追平永不切换，第二目标才是超过它。**
- **失分来源**:永不切换在可见 tick 上(合并计算)失分如下，身份模块能争取的就是这几块:
  - 跟踪器把绑定的 ID 换给了干扰车(误跟):0.176;
  - 目标换了新 ID 回来，承诺停在旧 ID 上(滞留):0.217。
- **Ours 自己额外丢分**:
  - TAH 记忆被错误承诺写坏;
  - PGIF 在目标可见时，把 15–24% 的 tick 判为缺席;
  - 回来后找回慢：受 K = 5 限制，至少要 3 s;6 s 内真实再捕获只有 0.60 / 0.62,re-ID 是 0.82。
- **设计原则(沿用 1016 §2.1)**:
  - 默认不切换;
  - 只在强证据下切换;
  - 怀疑 ID 被换走时，宁可撤销承诺，也不跟着错车飞。

## 2. 候选(全部是方法级开关，缺省 = Ours-CV 现行为;不重训神经网络)

身份决策只读图像框、裁剪特征和自身相机位姿，**不读 `world_xyz` / `depth_m`(真值)**。

| 编号 | 改动 | 针对 | 依据 |
|---|---|---|---|
| V1 | TAH 记忆只写承诺身份(已有开关 `identity.tah.memory_write: committed`);与 V3 同开时，还要求本 tick 通过校验才写 | 记忆被错车写入 | 单次 +0.055(承诺正确，不显著，未重复) |
| V2 | 受保护 gallery 融合:z = TAH logits + λ · gallery 分数。gallery 在开局窗口播种;之后只在「承诺身份 + 置信 + 通过校验」时写入，慢更新，保留多个视角(同 re-ID 的 K-view 规则) | 丢失后没有不被污染的外观记忆 | 离线 +0.03–0.06;re-ID 的恢复来自慢更新 gallery |
| **V3** | **承诺 ID 校验**。承诺 ID 本 tick 有框时检查两项:① 框的裁剪特征与受保护 gallery 的相似度;② 图像系位置 / 尺寸相对上一次可信观测的跳变(用自身位姿补偿相机运动)。连续 c 个 tick 不一致 → 判定 ID 被换走：停止写记忆、撤销承诺、进入搜索状态。**与 CV 的衔接**:估计器回滚到最后一次通过校验的位置，再按 CV 外推，避免拿换走后的错车位置外推 | 跟踪器 ID 互换(占丢失的 65–80%) | 1016 §1.2b;撤销本身不改变 M1,但能让无人机停止跟随错车 |
| V4 | 恢复通路：融合选择与承诺不一致(或处于搜索状态),且 gallery 分数领先 ≥ m、连续 N 个 tick(N < 5)→ 直接改承诺，并用该候选重置 TAH 记忆 | 回来后找回太慢 | 回来后 6 s 内，身份模块额外找回的只有 +0.04–0.15 |
| V5 | PGIF 缺席判定只在承诺 ID 无框时生效;开局窗口内保持现行为 | PGIF 挡住恢复 | 共享开局下去掉 PGIF:承诺正确 +0.10,再捕获 0.79;自然开局下整体去掉更差 → 只缩小作用范围，不整体去掉 |

**V3 + CV 的风险**:撤销承诺后，无人机按「最后一次通过校验的位置」外推。如果校验本身误报(把对的判成被换走),会把无人机带离目标。因此 V3 的阈值必须在调参种子上先估误报率(§4)。

**诚实框定(必须报告的消融)**:
- 只有 gallery(≈ re-ID)、只有 TAH、两者融合;
- re-ID + V3 + V4(臂 E):若 ≥ 我们，说明贡献只在校验与恢复通路，不在 TAH;
- **永不切换 + V3 + V4(臂 F)**:若 ≥ 我们,TAH 和 PGIF 都没有贡献，论文要按「跟踪器 + 校验 + 恢复」重新定位。

## 3. 验证流程

**第 1 步：设计与代码审查**
- §2 的实现交 codex 只读审查，直到 NO MAJOR ISSUES;
- 新增的开关按配置开关控制，缺省值必须逐位复现 Ours-CV(用 `replay_parity` 核对)。

**第 2 步：调参(不用 dev-B / test)**
- λ:在 dagger v3 / v3_val 上定。
- V3 的 c 与校验阈值、V4 的 m / N:需要带跟踪器 ID 的日志。
  - **建议**:新登记一组调参种子 93700–93739(登记前核对与其他段不重叠),打开 `trk` 记录，用 Ours-CV 采集 40 局，约 45 分钟;
  - 在这批日志上离线重放 V3 / V4,目标是误报率 ≤ 5%、ID 互换召回率尽量高。

**第 3 步:dev-B 闭环筛选(r = 1;对照直接复用 Ours-CV r0 和永不切换 r0 的已有运行)**
- Ours-CV 的已有运行 = `where_cv_devB3/cv_r0`(/ `cv_r1`)。它们与 `ours_cv` 的解析结果逐项相同，只有方法名、继承链和配置哈希的记账不同(10-19 核对),可直接作对照。

| 臂 | 内容 | 目的 |
|---|---|---|
| A | V5 | 改动最小 |
| B | V1 + V2 | 受保护记忆 |
| C | V1 + V2 + V3 | 加 ID 校验 |
| D | V1–V5 全部 | 完整方案 |
| E | re-ID + V3 + V4 | 消融：贡献是否来自 TAH |
| F | 永不切换 + V3 + V4 | 消融：「默认信任跟踪器」本身是否就够 |

- **检查点**:看 1 = 10 个种子，看 2 = 20 个种子，看 3 = 40 个种子(种子名单同 1019 §9.2)。边界 z = 4.0 / 2.81 / 点估计。
- **中期淘汰**:相对 Ours-CV 的 ΔM1 区间上界 < 0 → 淘汰(没有增益)。
- **提前晋级**:相对永不切换的 ΔM1 区间下界 > 0 → 提前进入第 4 步。
- **看 3**:按 M1 点估计排序。最好的一臂只有在「M1 ≥ 永不切换的点估计」且「TR90 不低于 Ours-CV 0.02 以上」时，才补跑 r = 1 并进入第 4 步;否则回到设计。dev-B 已被大量使用，筛选结论只作方向参考。

**第 4 步:test 预注册判定(Town05 95000–95079 × r = 2,共 160 局;两段式中途检查，1019 §8.2)**
- 臂：新 Ours、永不切换、re-ID,各跑 160 局。
- **主比较**:新 Ours − 永不切换，ΔM1 ≥ +0.05 且 CI 下界 > 0(中期用 99.5% CI;终检 z = 1.98)。
- 次要比较：新 Ours − re-ID。
- **门槛**:TR90 非劣效(CI 下界 > −0.02);身份耗时 p95 < 100 ms。
- **报告**:按 tick 合并的 M1、承诺正确、M2、真实再捕获(6 s 内)。
- **功效**:逐种子差的标准差约 0.25,80 个种子 × 2 遍时 CI 半宽约 ±0.055,观测差约 0.06 才能使下界 > 0。

**可选：解耦诊断(论文附录)**
- 最好的一臂与永不切换在专家飞行下各跑 40 局(同 P1)。
- 在飞行不再掩盖身份时报告身份效应(P1 中 U1 的上限是 +0.272)。
