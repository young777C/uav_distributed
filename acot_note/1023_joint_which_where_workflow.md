# 1023 WHICH × WHERE 联合迭代 workflow 设计稿(讨论稿，未改代码)

2026-10-23。依据 `1020_stress_scenario_design.md`(场景与协议)、`1023_stress_baselines.md`(基线)、`1023_main_metrics_prereg.md`(主指标，路径 B:TR、M1、RA@6s、FRA@6s),以及本文 §1.3 的离线飞行归因(`runs/stress/flight_exit_attr.py`,只读已有日志)。

## 0. 结论速览

1. **两个模块各有很大空间，而且互相耦合**。
   - WHICH:专家回放下，U1 的 M1 比 re-ID 高 0.31,RA@6s 高 0.56;Ours-CV 还落后于 re-ID,主要问题是错锁。
   - WHERE:自主飞行时，目标在画面内的时间只有 31–46%,专家飞行是 79%;39 局里有 30–37 局被截断。
   - 耦合:**自主飞行下，目标出画时约一半是在跟着克隆车**(U1 为 24/55 次)。飞得远会使跟踪器 key 抖动增加 10 倍，抖动又导致 key 被转给克隆车。
2. **单靠现有的 autotune 循环做不到联合优化**。它的 G3 只在专家飞行的录制上回放，帧与决策无关，所以**测不出 WHERE 的任何改动**。
3. **建议的结构是三条线加一个总审计**:
   - **W 线**(WHICH):沿用现有循环，补两项改动(护栏加 RA / FRA;增加"U1 自飞录制"回放集，防止只对专家视角过拟合);
   - **F 线**(WHERE):新建闭环门控。用真值身份(U1)飞，排除身份噪声，只评飞行;
   - **J 线**(联合):处理同时改两个模块的"身份感知飞行"候选，并在任一条线晋升后做闭环集成检查;
   - **最终审计**:dev-S 上做 2×2 析因 {re-ID, Ours} × {旧 WHERE, 新 WHERE}。它既能算出各模块的贡献，也保证基线拿到同样的新飞行，比较公平。
4. **开跑 F 线之前，先做 WHERE 的第 0 步诊断**(§3)。要判断瓶颈在航点估计(便宜，调参即可)还是在 DiT 控制器(贵，需要重训)。这决定 F 线改什么。

## 1. 现状与提升空间

### 1.1 要超过的基线(路径 B 主指标)

| 表 | 指标 | re-ID(要超过的对象) | Ours-CV(现在) | U1(上界参照) |
|---|---|---|---|---|
| A:专家回放(WHICH) | M1 | 0.605 | 0.579(−0.026,不显著) | 0.915 |
| | RA@6s | 0.412 | 0.330(−0.083,显著) | 0.974 |
| | FRA@6s | 0.218 | 0.436(+0.218,显著) | 0.071 |
| B:自主飞行(端到端) | TR | 0.196 | 0.236(+0.040,不显著) | 0.247 |
| | M1 | 0.725 | 0.578(−0.148,显著) | 0.810 |

OA-VAT(身份模块替代版)在表 A 上显著弱于 re-ID;在表 B 上与 re-ID 无显著差别。永不切换、DeepSORT、OC-SORT 都更弱。

### 1.2 WHERE 的空间(自主飞行 vs 专家飞行，同为压力场景)

| | 专家飞行(回放录制) | 自主飞行(re-ID / U1 / Ours-CV) |
|---|---|---|
| 目标在画面内的时间占比 | 79% | 31% / 36% / 46% |
| 截断局数 | 0 | 35 / 34 / 30(共 39 局) |
| 与目标的距离(中位数) | 39 m | 76 / 75 / 107 m |
| 目标框尺寸 px(中位数 / 下四分位) | 29.4 / 25.9 | 26.1 / 16.4、24.7 / 14.8、21.5 / 14.4 |
| 跟踪器 key 抖动率 | 0.010 | 0.072 / 0.105 / 0.113 |

- 专家飞行下 U1 的 TR90ˣ 约 0.76(近似值),自主飞行下为 0.247。**飞行这一侧的空间是身份侧的数倍**。
- 但专家是全知的，这个差距不等于可部署的飞行上限，见 §3。

### 1.3 耦合：目标为什么出画(离线归因，出画段 ≥ 1.2 s)

按出画前最后一个 S2 tick 的承诺状态分类：承诺在目标上(follow 或 stale_target),说明是**飞行没跟住**;承诺在干扰车上(misled 或 stale_wrong),说明是**身份把无人机带走**。

| 臂 | 出画次数 | 承诺在目标上 | 承诺在干扰车上 | 其中导致截断的那次出画:目标 / 干扰车 |
|---|---|---|---|---|
| U1 | 55 | 31 | **24** | 21 / 16 |
| re-ID | 68 | 32 | 36 | 16 / 22 |
| Ours-CV | 73 | 25 | **48** | 10 / 24 |
| OA-VAT | 55 | 28 | 27 | 17 / 18 |
| 永不切换 | 60 | 39 | 21 | 23 / 15 |

**解读**
- **U1 的身份头不会选错，但 44% 的出画仍发生在承诺落在克隆车上时**。原因是跟踪器把 key 转手，K = 5 迟滞又一时换不回来(`1023_main_metrics_prereg.md` §5)。
- 也就是说，**改善 WHERE 能直接改善 WHICH 的结果**:飞得近，框更大、key 抖动更少，转手就更少。
- **Ours-CV 的出画主要由身份造成**(48/73),而且它飞得最远(107 m)。所以修 WHICH 的错锁同样会改善 TR。
- 结论：两个模块不能完全分开优化;但可以**分开评估**,再用联合门控收口。

## 2. 设计原则

1. **能解耦评估就解耦，必须耦合时才在闭环里评**:
   - WHICH 在固定帧上回放：快、确定、可配对;
   - WHERE 用真值身份(U1)在闭环里飞，排除身份噪声;
   - 联合候选和集成检查在闭环里端到端评。
2. **门控指标与论文主指标(路径 B)对齐**。主判据和护栏都写成单侧下界，并事先定好阈值。
3. **防止对专家视角过拟合**:W 线增加"当前最佳 WHERE + U1"的自飞录制集(G3-SF)。这样候选也要在远距离、高抖动的视角下不变差。
4. **用析因设计做归因**:最终审计用 {re-ID, Ours} × {旧 WHERE, 新 WHERE}。论文可以分别报告身份贡献、飞行贡献和交互项;"身份感知飞行"的新意就体现在交互项上。
5. **守住特权边界**(1020 Q2):
   - WHERE 只能读**承诺框对应车辆**的真值坐标;
   - 其他候选只能用图像空间信息(框的位置、大小，不涉及真值);
   - 身份代码不读任何真值。
   - 若要让 WHERE 读非承诺车辆的真值坐标，须升协议版本，并由用户拍板。
6. **种子隔离**:F 线和 J 线用新的调参集和确认集;**dev-S 只用于最终审计**;Town03 测试集锁定不动。

## 3. WHERE 第 0 步：先搞清楚飞行瓶颈在哪(预注册后再跑)

在 F 线的调参集上做(U1 身份，各 40 局，配对):

| 臂 | 航点来源 | 控制器 | 回答的问题 |
|---|---|---|---|
| L0 | 现行 WHERE(CV 估计器) | DiT | 现状 |
| **L1** | **目标真值位置**(新诊断通道 `oracle_where`) | DiT | 航点完美时，DiT 能不能跟住 |
| **L1b** | 真值，但只在目标可见时提供(P1b,非全知) | 专家 PID | 可部署控制的参照上限 |
| L2 | 全知真值 | 专家 PID | 全知上界(已有 `diag_oracle_head_expert`) |

**判读(阈值事先定)**
- **L1 接近 L2**:瓶颈在航点估计、丢失后的搜索和站位。F 线只改 `_where`、`TargetStateEstimator`、frame_gain、搜索策略，便宜。
- **L1 接近 L0,且远低于 L2**:DiT 控制器跟不住航点。只能在三条路里选一条：在 DiT 外加残差控制(PID 或 frame_gain 修正)、对 DiT 做飞行 DAgger 微调(贵)、或者接受现状。**须用户拍板**。
- 同时记录：与目标的距离、目标框尺寸、key 抖动、出画归因(§1.3 的口径)。

**实现**:新增诊断通道 `oracle_where`,涉及 `gt_sites.yaml`、`policy.py` 的 `_where` 诊断分支和审计。代码先过 codex。

## 4. 三条线的门控

### 4.1 W 线：身份(沿用 acot-autotune,少量改动)

| 门 | 内容 | 判据 | 时间 |
|---|---|---|---|
| G1 | 静态检查(现状) | 同现状 | 秒级 |
| G2 | 8 局专家回放(现状) | 无明显退步 | 2–4 min |
| G3-tune | 114 局专家回放 | ΔM1 单侧 95% 下界 > 0;按 tick 合并的 ΔM1 > −0.02;**新增**:ΔFRA@6s 上界 < +0.02,ΔRA@6s 下界 > −0.02 | 约 20 min |
| **G3-SF(新增)** | 在"当前最佳 WHERE + U1"的自飞录制上回放(40 局，调参集种子) | ΔM1 ≥ −0.02(非劣) | 约 8 min |
| G3-confirm | 隐藏确认集(现状) | 只回报通过 / 不通过 | 约 13 min |

- G3-SF 的录制在 F 线每次晋升后重录一次(闭环约 2 h)。
- 起点：先评估 DAgger 重训后的 TAH,与 re-ID 比较，取 G3 上更好的一个。

### 4.2 F 线：飞行(新建闭环门控)

- **可以改的范围(由 §3 决定)**:
  - `acot/runtime/policy.py` 的 `_where` 和 `act` 中的动作修正部分;
  - `rollout/target_state.py`;
  - control 配置项：站位距离、高度、frame_gain、丢失后的搜索方式;
  - DiT 权重只有在 §3 判定控制器是瓶颈、且用户同意后才允许改。
- **身份代码不许改**。

| 门 | 内容 | 判据 | 时间(4 worker,每卡 1 CARLA + 1 策略) |
|---|---|---|---|
| F1 | 静态检查：改动范围、真值通道 | 只允许协议规定的通道 | 秒级 |
| F2 | U1 身份闭环，12 局(飞行调参集) | TR_U1 与画面内占比无明显退步;序贯判定，可提前停止 | 约 40 min |
| F3 | U1 闭环 40 局 + 当前最佳可部署 WHICH 闭环 20 局 | TR_U1 的 Δ 单侧下界 > 0;可部署 WHICH 下 TR 不变差、M1 不降超过 0.02;截断局数不增加 | 约 2–2.5 h |

- F 线前期**先做低成本参数扫描**:站位距离、高度、frame_gain、丢失后的搜索方式，跑 F2,不需要 LLM。
- 参数扫完、空间收窄后，再交给 LLM worker 做结构性改动。

### 4.3 J 线：联合(身份感知飞行 + 集成检查)

**候选类型**:同时改动 WHICH 和 WHERE 文件。例如:
- 身份不确定时，把"前两个假设的框"一起框进画面，而不是只追承诺的框;
- 有歧义时拉近距离以提高分辨率;
- 丢失后朝 WHICH 预测的目标位置搜索，而不是朝承诺框外推(承诺框可能已是克隆车);
- 换承诺的那几 tick 先不急转。

**门控**:身份部分先过 G3-tune 和 G3-SF(非劣即可);然后在联合调参集上做闭环，40 局端到端。
- 判据:TR 的 Δ 下界 > 0,且 M1、FRA@6s 不变差。

**集成检查**:W 线或 F 线任一晋升后，把"最佳 WHICH × 最佳 WHERE"在联合调参集上闭环跑一次，确认收益可以叠加，不是互相抵消。

### 4.4 最终审计与论文实验

| 对象 | 内容 |
|---|---|
| dev-S(从不对 agent 展示) | 2×2 析因 {re-ID, Ours WHICH} × {旧 WHERE, 新 WHERE},外加 U1、永不切换、OA-VAT 在新 WHERE 下的结果;路径 B 主指标 |
| 测试集(锁定，只跑一次) | test-seen + test-unseen(Town03),r = 2 |
| OA-VAT 完整版 | 自带遮挡感知规划，是天然的"WHICH + WHERE 联合基线"。`oavat_full.py` 已写好，**建议接入** |

**"超过基线"的判据(事先定)**
1. 表 A:Ours WHICH 相对 re-ID,ΔM1 下界 > 0,ΔRA@6s > 0,ΔFRA@6s ≤ 0。
2. 表 B:Ours(新 WHICH + 新 WHERE)相对两个对照都要 ΔTR 下界 > 0、ΔM1 > 0:
   - re-ID + 旧 WHERE;
   - re-ID + 新 WHERE(排除"只是飞行更好"的解释)。
3. 析因的交互项单独报告(身份感知飞行的贡献)。

## 6. acot-autotune 需要的改动

1. 组件新增 `where` 和 `joint`(现在 `MODELS = (identity_head, stage2)`)。在 `runtime_acot.py` 中按组件分派门控:`where` 走 F1→F2→F3,`joint` 走 G3 + J 闭环门控。
2. F2 / F3 / J 门控复用最终审计已有的闭环机制(调度、worker 与端口、配对)。新增 U1 闭环臂和序贯判定。
3. W 线护栏改为 M1 + RA@6s + FRA@6s,在 `gates/metrics.py` 中新增，不改动已有字段。新增 G3-SF 回放集。
4. **以上改动会改变工作流定义，必须新开 run 3**(Temporal 确定性的要求)。旧 run 5dea0352 仍停在准备阶段，可以存档。
5. 主控的任务卡标注所属线(W / F / J)。F / J 线的闭环容量有限，同一时间最多一个候选在跑 F3 或 J 门控。
6. 知识库补充：今天的发现(key 转手、距离与 key 抖动、出画归因)、§3 的结论、特权边界。

## 7. 风险

| 风险 | 对策 |
|---|---|
| WHICH 只在专家视角上调好，换到自飞视角就失效 | G3-SF + J 线集成检查 |
| 闭环噪声大、局数少 | 同种子配对、按步固定随机数(per_step)、序贯判定;F3 / J 用 40 局 |
| 被质疑"只是飞行变好了" | 析因审计;基线同样拿到新 WHERE |
| 特权信息越界 | WHERE 只读承诺框对应车辆的真值;其余只用图像空间;静态检查 + 审计 |
| DiT 控制器是瓶颈、需要重训 | §3 先判定;CVPR 版降级为只改航点和站位 |
| 时间不够 | 交替推进作为备选;J 线可缩为只做集成检查 |
