# 1004 开局身份修复:属性分类器开局(OPENING=attr)

> 目标:4 小时内把开局正确锁定率提到 ≥ 90%(2026-10-03 06:30 启动,10:30 截止)。不要求创新性。
> 状态:**已达标**。最终配置为 **v1**(`OPENING=attr OPENING_CFG={"window":3,"ft":0.5}` + `HIRES=3`)。
> - 留出种子闭环开局锁对 **91.5% [85.5, 95.2]**(n = 130),同种子 head 基线 35.4%,McNemar p = 1e-18。
> - dev 下游(n = 19,对 H-A):承诺正确锁定比例 **+0.27**(p = 0.001),最长连续正确 **+9.4 s**(p = 0.003),最长锁错 −3.1 s(不显著)。
> - 变体 v3 / v4 的开局率分别为 93.3% / 92.2%(全新种子)，但下游都不如 v1,因此不采用，见 §4。
> - 所有数字都标明来源(离线快照 / 闭环)和种子集合。

## 1. 问题与诊断(动机,已测)

- 部署设定 v2(调后跟踪器 ID + 射线遮挡感知候选)下，最终模型 H-A(TAHRelM + PGIF tempered + absent-hold)的**闭环开局正确率只有 8/19 = 42.1%**(dev 91000–19,`opening_cl.py --stem v2h_pgif_trk`)。
- 开局正确与否解释了单集承诺正确率方差的大部分(R² 0.78–1.00,`reacq_factors.py`)。因此开局是重捕获正确率的第一杠杆。
- 根因:语言 grounding 头用的是 Qwen3-VL-4B 第 24 层的池化特征。512² 输入下每个视觉 token 覆盖约 32×32 px,一辆车只占 1–2 个 token,头因此学到了「画面中心」先验。非中心目标的准确率只有 27%,随机水平是 20%。
- 逐步排查(离线开局快照基准，种子 dev2 93000–99 n=98、dev 91000–19 n=18,t=0 准确率):

| 打分器 | 输入 | dev2 | dev |
|---|---|---|---|
| S0 当前 grounding 头 | 512² 全图 | 35.7% | 55.6% |
| S1s 放大核验(Qwen yes/no,spotlight,3×box) | 3× 高清开局帧 | 59.2% | 72.2% |
| S3 属性分解(Qwen 颜色问 + 车型问) | 3× 高清开局帧 | 67.3% | 88.9% |

  结论:同色场景下 Qwen 认不出 CARLA 车型(41–57%),颜色也只部分可靠。瓶颈在**细粒度属性识别**,不在定位。

## 2. 方案:属性分类器开局(GT-free 运行时)

运行时只用三样输入：相机帧、候选框、语言指令。

1. **高清开局帧**:开局 tick 0/6/12 由同位姿 k=3 相机(1536²)提供帧。只在这 3 个 tick 使用，step ≥ 12 后销毁(`env.py hires_k`,`--hires 3`)。候选框按比例映射到高清帧上裁剪真实像素。
2. **语言解析**:`describe()` 去掉方位和距离后，解析出(颜色词, 车型名词)。
3. **属性打分**:对每个候选计算
   `score = log p(车型名词 | 裁剪) + log p(颜色词 | 裁剪)`,两个对数概率都取自两个头的平均:
   - 线性头：冻结的 DINOv2 ViT-S/14(CLS + 均值 patch)。颜色头另外拼接框内 RGB 直方图。温度在留出种子上校准。
   - 微调头：解冻 DINOv2 最后 4 个 block,加车型 / 颜色双头。增强包括尺度和平移抖动、水平翻转、亮度。测试时做翻转 TTA。
   - 两者按 `ft=0.5` 等权混合(对数概率层面)。
4. **开局窗口(最终 v1,`OPENING_CFG={"window":3,"ft":0.5}`)**:窗口为 3 个 tick(0/6/12)。
   - 每个 tick 先把分数减去当 tick 最大值，再按跟踪器 ID 累加，取 argmax。
   - 前两个开局 tick 会重置 TAH 记忆，再写入当 tick 的开局选择。最后一个 tick 不重置:TAH 用已有记忆(t=6 的样本)打分并写入。PGIF 正常累积证据。
   - 开局选择替换 `lang_slot`,对所有 head 的冷启动生效。
   - 试过的变体(v2 `agg=mean`、v3 `agg=last + final_reset + reset_asd`、v4 `agg=last + force_final + seed_asd`)都通过 `OPENING_CFG` 开关实现，默认关闭，对比见 §4。

**训练数据(与评测严格分离)**:种子 96000–96279(280 集，每集 13 步)。开局 tick 0/6/12 的高清快照，加上环境导出的候选属性标签(`DUMP_LABELS`:目标和干扰车的 blueprint 与颜色)。共 17,420 个裁剪(含翻转和两种尺度),覆盖 17 个车型、18 个颜色。GT 只用于**训练**分类器和**打分**。
场景歧义上限：训练集里 8/280(2.9%)的场景存在颜色和车型都与目标相同的干扰车，所以属性方法的理论上限约 97%。

## 4. 闭环验证(部署设定 v2,最终模型配置)

配置：TAH + PGIF tempered(resid_decay 0.98)+ absent-hold(max 8)、调后跟踪器、射线遮挡感知候选、`OPENING=attr OPENING_CFG={"window":3,"ft":0.5}`、`HIRES=3`。

**V. 留出开局验证**:每集 19 步(S2 tick 0/6/12/18),与最终模型配置一致。`runs/opening_dump/run_openval.sh`;统计用 `opening_cl.py`,配对比较用 `opening_pair.py`。
开局锁定的口径是:**窗口结束后**(首个满足 t ≥ 12 且目标在候选中的 S2 tick)policy 承诺的身份等于目标。首个 tick 的结果一并报告。

| 版本 | 种子(均未用于训练) | 窗口后开局锁对 | 首个 tick |
|---|---|---|---|
| head 基线(当前 grounding 头) | 93100–93239 | 46/130 = 35.4% [27.7, 43.9] | 51/132 = 38.6% |
| **v1** attr(`{"window":3,"ft":0.5}`) | 93100–93239(与 head 同种子配对) | **119/130 = 91.5% [85.5, 95.2]** | 126/132 = 95.5% |
| v2 = v1 + agg=mean + final_reset + reset_asd | 93240–93379 | 116/130 = 89.2% [82.7, 93.5] | 127/133 = 95.5% |
| **v3** = v1 + agg=last + final_reset + reset_asd | 93380–93519(全新，无偏) | **125/134 = 93.3% [87.7, 96.4]** | 129/137 = 94.2% [88.9, 97.0] |

| v3 合计 | 两组种子合并 | 247/263 = 93.9% [90.3, 96.2] | — |
| v4 = v1 + agg=last + force_final + seed_asd=3 | 93520–93659(全新) | 119/129 = 92.2% [86.3, 95.7] | 122/133 = 91.7% |

- 配对检验(同种子 93100–93239,窗口后):
  - v1 对 head:不一致对 77:4,McNemar p = 1e-18;
  - v3 对 head:77:2,p = 1e-20;
  - v3 对 v1:9:5,p = 0.42,差异不显著。
- **报告口径**:v3 的主数字是全新种子上的 93.3% [87.7, 96.4]。合并 263 集为 93.9% [90.3, 96.2],CI 下界超过 90%,但其中一半种子参与过 v3 的设计，只作为辅证。
- **失败分析(v1,11 例)**:
  - 6 例:开局窗口内**跟踪器把目标和干扰车的 ID 互换或切换**,而 t=0 本来是认对的。按 ID 跨 tick 累加，会把旧 ID 的历史证据带给干扰车。同时 PGIF 已为旧 ID 累积证据，会抵抗切换。
  - 2 例:ID 没变,t=0 也认对，但 t=12 时 TAH 记忆自己的 argmax 覆盖了开局选择。原因是窗口最后一个 tick 不重置记忆。
  - 3 例:t=0 就认错车，属于属性识别错误。
- **v2 的教训**:按 ID 求均值并不能解决 ID 互换。互换后，旧 ID 的高分历史仍然跟着干扰车走;而 v2 又关掉了原来 t=12 时 TAH 按外观纠正的那条路。结果是 89.2%,没有改善。
- **v3**:每个开局 tick 只用**本 tick 的分数**做决定，不跨 tick 按 ID 聚合，因此不受 ID 互换影响。窗口最后一个 tick 的选择同时播种 TAH 记忆和 PGIF。离线(仿真 ID)「只用最后 tick」= 97.5%(n=118)。v3 在 4+4 集冒烟(其中含 3 个 v2 的 ID 互换失败种子)中全部锁对。
  - 选择偏差说明:v2/v3 的设计都是看了留出种子上的失败后做的，所以 v3 的报告数字只取**全新**种子 93380–93519。

  - 「逐 tick 决策」虽然避开了 ID 互换，却改变了开局后记忆和 PGIF 的初始化，下游反而受损。
  - 跟踪器在开局窗口内互换 ID,是 v1 剩下约 5% 开局失败的主因。根治要靠跟踪器本身(更高频关联或外观门控)，而不是开局逻辑。这一条列为后续工作。

## 5. 注意事项与公平性

- **部署性**:运行时 GT-free。分类器的训练标签来自模拟器(独立种子)，性质上等同于在域内训练一个检测器或属性识别器。原 grounding 头同样在 CARLA 数据上训练。
- **闭集词表**:车型头是 CARLA 的 17 类闭集。语言指令里出现训练集没有的车型时，该项记 0(只用颜色)。真实部署需要开放词表的属性识别器。论文里应如实写明，这是「模拟器内的属性感知上限」类模块。
- **高清开局帧**:假设无人机可以在开局时获取一次 3× 分辨率的静帧(或光学变焦)。只用于 tick 0/6/12。
- **与外部基线的公平性**:外部基线(DAM4SAM 等)的初始化如果来自我们的语言开局，就应该与 Ours 共享**同一个开局模块**。否则「开局更好」会被混进跟踪器比较里。1004 预注册里的共享开局 / 自然开局两类实验要按这个原则更新(待定)。
- 本节的方案和数字均为 dev 阶段结果，没有触碰 test 种子(95000+)。
