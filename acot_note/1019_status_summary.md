## 2. 评测协议与指标

**协议 `sim_proxy_v2@3`**(所有方法相同)
- 仿真 10 Hz,每 6 帧一个 S2 tick(0.6 s);每局最长 900 帧(90 s);目标连续出画 18 s 即截断。
- **理想化感知**(所有臂相同，协议明文声明):
  - 候选框 = 任务车辆的真值投影框，经射线遮挡过滤(被遮挡的车没有框);
  - 匈牙利跟踪器 + DINOv2 外观分配 ID;
  - **WHERE 用承诺框对应车辆的真值世界坐标**。
- **承诺规则**:置信度 ≥ conf_tau 才算一票;换人需要同一个挑战者连续 5 票(约 3 s)。
- **防作弊**:
  - 真值通道分级(`1004_code_framework.md` §7);
  - 每局真值访问审计 `gt_access.json`;
  - 诊断臂必须声明所用的真值通道，不得进入主表。

**指标**

| 指标 | 定义 | 地位 |
|---|---|---|
| **M1 严格跟随率** | 目标有框的 tick 中，承诺 ID 本 tick 的框正好是目标的比例(不沿用旧 ID) | **新主指标**(10-19,test 前修订) |
| 承诺正确 pc_correct | 目标在画面内的帧中，承诺 ID 对应目标的比例;ID 本帧无框时沿用它最后匹配到的车 | 旧主指标，照报 |
| **TR90** | 承诺正确的帧数 / 900(固定 90 s;出画帧和截断后的帧都不算) | 安全指标(非劣效界限 δ = 0.02) |
| M2 误跟率 | 承诺 ID 的框是干扰车(无人机正飞向错车)的比例 | 安全指标候选 |
| 再捕获(6 s 内) | 目标重新出现后 6 s 内达到严格跟随的比例 | 次要，描述性 |

> **M1 的已知偏差**:按局平均会放大短局;承诺跟错后，目标往往随即出画，不再计入分母。所以 M1 必须与 TR90 一起看，建议同时报告「按 tick 合并」的版本。以永不切换为例：按局平均是 0.685,按 tick 合并只有 0.607。

### 2.1 三个指标的计算公式(10-23 补)

**记号**
- 一局有帧 $f = 0,\dots,F-1$($F$ = 900,满 90 s),S2 tick 为 $t \in \mathcal{T} = \{0, 6, 12, \dots\}$(每 6 帧,一局 150 个)。
- 每个 tick 记录:候选框的跟踪器 key 集合 $K_t$、每个 key 的真值身份 $g_t(k)$($-1$ = 目标,$d_j$ = 第 $j$ 辆干扰车)、身份模块的承诺 key $c_t$(未承诺时为空)。
- **key → 车辆**:$a_t(k) = g_t(k)$ 若 $k \in K_t$;否则沿用该 key 最后一次被匹配到的车辆(从未匹配过则为空)。
- **帧状态** $s_f$:`v` = 在画面内且未遮挡;`o` = 在画面内但被遮挡;`x` = 出画。
- **tick 状态**(只看 $c_t$):
  - **follow**:$c_t \in K_t$ 且 $g_t(c_t) = -1$(承诺的 key 本 tick 有框,且框是目标);
  - **misled**:$c_t \in K_t$ 且 $g_t(c_t) \neq -1$(框是干扰车);
  - **stale_target / stale_wrong**:$c_t \notin K_t$,沿用的车辆分别是目标 / 干扰车;
  - **none**:未承诺,或 key 从未匹配过。

**① M1 严格跟随率**(主指标;`gates/metrics.py:50` ← `runs/headroom/headroom_m1.py`)

$$
M1 = \frac{\sum_{t \in \mathcal{T}} \mathbb{1}[\,-1 \in g_t(K_t)\,] \cdot \mathbb{1}[\,\text{state}_t = \text{follow}\,]}{\sum_{t \in \mathcal{T}} \mathbb{1}[\,-1 \in g_t(K_t)\,]}
$$

- **分母**:目标**有框**的 tick,即在画面内且未被遮挡。出画、遮挡、E3 镜头移开期间的 tick 都不计入。
- **分子**:只计 follow。stale_target(被遮挡时沿用旧 key)、misled、none 都不算跟随。
- 衡量的是:**看得见目标时,有没有认对、并且已经切到它当前的 key**。

**② 承诺正确**(旧主指标)

有两个实现,定义相同,粒度不同。
- **逐帧版 `pc_correct`**(`acot_client/scoring.py:62-97`,写入 `episode.json`):
  $$
  \text{pc\_correct} = \frac{\sum_{f} \mathbb{1}[\,s_f \in \{v, o\}\,] \cdot \mathbb{1}[\,a_f(c_f) = -1\,]}{\sum_{f} \mathbb{1}[\,s_f \in \{v, o\}\,]}
  $$
  分母是目标**在画面内**的帧,**含被遮挡帧**。$c_f$ 是该帧服务端回传的承诺 key,在 S2 tick 之间保持不变。承诺的 key 本帧无框时,沿用它最后匹配到的车辆;未承诺的帧算不正确,所有方法一致。**自主飞行(dev-S)的表用此版**。
- **逐 tick 版 `pc_tick`**(`gates/metrics.py:50`,回放用):
  $$
  \text{pc\_tick} = \frac{\#\{t:\ s_t \in \{v, o\},\ \text{state}_t \in \{\text{follow}, \text{stale\_target}\}\}}{\#\{t:\ s_t \in \{v, o\}\}}
  $$
  **专家飞行回放(G3 调参集)的表用此版**。
- 与 M1 的差别:遮挡期间继续承诺原目标也算对(stale_target 记为正确),所以对"不轻易换人"更宽容。永不切换、DeepSORT 的承诺正确(约 0.67–0.73)远高于 M1(约 0.33),原因就在这里。

**③ TR90 跟踪率**(安全指标;`acot_client/scoring.py:12,100`)

$$
\text{TR90} = \frac{\sum_{f=0}^{F-1} \mathbb{1}[\,s_f \in \{v, o\}\,] \cdot \mathbb{1}[\,a_f(c_f) = -1\,]}{H}, \qquad H = 900
$$

- 分子与逐帧 `pc_correct` 的分子相同。
- 分母是**固定时长 $H$ = 900 帧**,不是可见帧数。出画帧、目标连续出画 18 s 被截断后剩余的帧,全部记为未跟踪。
- 因此 TR90 同时反映**飞行**(能否把目标留在画面里)和**身份**(留住的是不是目标)。
- 专家飞行回放没有可比的 TR90,只报近似值 $\text{TR90}^{x} = \text{pc\_tick} \times n_{\text{in}} / 150$($n_{\text{in}}$ = 在画面内的 tick 数)。它反映的是专家飞行加上该方法的身份判断,不是该方法自己的跟随率。

**汇总与比较(三个指标相同)**
- **按局平均**(主口径):$\bar{M} = \frac{1}{N}\sum_{i} M_i$。
- **按 tick 合并**(护栏口径,仅 M1):$M1_{\text{pooled}} = \sum_i n^{\text{fol}}_i \big/ \sum_i n^{\text{vis}}_i$。
- **方法间比较**:同一组种子逐局配对,差值 $\Delta_i = M_i^{A} - M_i^{B}$;10,000 次配对 bootstrap 求 95% CI,随机种子固定(`gates/metrics.py:80`)。只用各方法都完成的种子(取交集)。

### 2.2 出画后重新捕获指标(10-23 提案;`runs/stress/reacq_metrics.py`)

M1 把"看得见时认得对不对"和"丢失后能否找回"混在一起。压力场景的核心难点是后者,所以单独以**事件**为单位度量。粒度为 S2 tick,$\Delta = 0.6$ s。

**事件定义**
- **丢失段**:目标连续 $\ge L$ 个 tick 没有框($L$ = 2,即 ≥ 1.2 s;原因可以是出画、遮挡或 E3 镜头移开),且之前至少有过一个有框的 tick(开局不算)。
- **重新入画** $t_e$:丢失段之后,目标第一次重新有框的 tick。
- **换 key**:$t_e$ 时目标的跟踪器 key 与丢失前不同。这是难的情形:目标拿到了新 ID,必须主动切过去。
- **成功时刻** $t^\*$:窗口 $[t_e,\ t_e + W)$ 内($W$ = 10 tick = 6 s),第一个满足以下条件的 tick:状态为 follow,并且目标下一次有框时仍为 follow。后一条是为了去掉一闪而过的偶然命中。
- **截尾**:窗口还没走完一局就结束了,且没有成功。这类事件不计入任何分母。

**④ RA@6s 重新捕获正确率**(越高越好)

$$
\text{RA@}W = \frac{\#\{e:\ t^\*_e \text{ 存在}\}}{\#\{e:\ \text{未截尾}\}}
$$

另报**换 key 子集**的 RA,作为身份能力的纯度量。key 不变的事件,只要不换人就自动成功。

**⑤ TTR / RMTR 重新捕获所需时间**(越低越好)

$$
\text{TTR}_e = (t^\*_e - t_e)\,\Delta, \qquad
\text{RMTR@}W = \frac{1}{|E|}\sum_{e \in E} \min(\text{TTR}_e,\ W\Delta) \quad (\text{失败按 } W\Delta = 6\text{ s 计})
$$

- 主报 **RMTR**(受限平均时间):它把"找不回"按 6 s 计入,不会因为只统计成功事件而偏乐观。
- 另报成功事件的 TTR 中位数。
- U1 的 TTR 中位数为 2.4 s,恰好是 K = 5 迟滞的下限(4 个 tick)。这个下限是所有方法共享的规则,不能靠身份模块消除。

**附:WL@6s 错锁率**:窗口内在成功之前出现过 misled(承诺的框是干扰车)的事件占比。错锁会把无人机带向错车,是安全指标。

|---|---|---|---|---|---|---|---|---|---|---|---|

**解读**
- **区分度远高于 M1**。专家回放下,U1 与 re-ID 的 RA 差 0.56(M1 只差 0.31);换 key 子集上,永不切换和两个 MOT 跟踪器基本为 0。这清楚地说明它们"不会找回"。

- 弱方法的 TTR 中位数为 0,是因为它们的成功几乎全部来自 key 不变的事件。所以应以 RMTR 和换 key 子集的 RA 为准。

**口径注意**
- 专家回放下,各方法共享同一份录制,事件基本相同(262–267 个,差别来自跟踪器的再运行),可以逐局配对。
- 自主飞行下,事件由各方法自己的飞行产生,数量不同(41–63 个)、难度也不同,**不能严格配对**。只能作描述性比较,或者按事件类型分层。
- 自主飞行下 U1 的 WL 达到 0.386,高于预期。初步判断:贴近飞行时,跟踪器会把原来属于目标的 key 转给相邻的克隆车,此时承诺的 key 被判为 misled;这不是身份头选错。尚待逐例核实。

## 5. 差距从哪里来

**身份(Ours 低于下限)**
- **丢失的主因**:65–80% 的丢失是共享跟踪器把承诺的 ID 换给了干扰车，不是身份模块主动改错。
- **找不回来**:
  - TAHRelM 的记忆被错误的承诺写坏;
  - PGIF 在目标可见时，把 15–24% 的 tick 判成「缺席」,挡住了切回目标。
- **再捕获**(6 s 内，真实落在目标框上):
  - re-ID 0.82,永不切换 0.65,Ours 0.60 / 0.62;
  - 6 s 以上的长缺口基本找不回来(0.1–0.25)。
- **永不切换得分高的原因**:
  - 开局 84% 选对;
  - 匈牙利跟踪器在短遮挡后多会把原 ID 还给目标;
  - 认错后目标随即出画，不计入分母。

**帧的构成(U1,模型自己飞)**
- 可见 38%,遮挡 21%,出画 42%。
- **遮挡帧上任何身份头都无法投票**:U1 与永不切换在遮挡帧上认对率相同，都是 0.46。

**WHERE / 飞行**
- 承诺 ID 有框时：用真值坐标 + 匀速估计器生成航点。
- 承诺 ID 无框时：原版用 EAR 航点，离线位置误差比匀速外推大 2–6 倍;现已按复验结果改用 CV。
- **飞行丢目标是 TR90 的主瓶颈**:身份完美(U1)时 74/80 局被截断。
