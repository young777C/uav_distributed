## 实施偏离(相对设计 v4 的文字)

- **D1 TrafficManager 种子不随重复编号变化**(设计 §3.5 写的是 H(种子, r))。原因:TM 种子即场景种子，场景也用它设随机数;随重复改变会改变交通流，等于换场景。重复之间只换策略随机数的盐;CARLA 侧的非确定性仍由 A/A 量化。
- **D2 UAST 不纳入**(按 §5.6(c) 预注册规则)。公开的 `UAST_track/epoch50.pth` 只含规划网络(深度主干 127 个张量、掩码主干 67 个、轨迹头 6 个),孪生目标定位分支不在其中;模拟器版本的目标掩码由已知目标位置几何投影生成(`UAST/test_uast_track.py` 约 762–812 行),没有可移植的身份机制。
- **D3 U2(记忆用真值刷新)按 acot 定义实现**:只把写入 TAHRelM 记忆的槽位换成真值槽位，选择、PGIF、承诺、开局与 Ours 相同。旧运行时的 `gallery_seed=gt` 路径没有属性开局与冷启动，因此 U2 不做与旧运行时的逐位一致核对。
- **D4 re-ID 的 PGIF 门控为空操作**(与旧代码一致):旧 `_asd_gate_memory` 对 reid 不改 gallery(gallery 存的是承诺身份，由 PGIF 改写的承诺在下一 tick 进入 gallery);首版移植误用了旧代码非门控模式的 `_asd_reset_memory`(重置 gallery),G8 回放发现后改正。
- **D5 `force_conf = false` 的语义**:PGIF 改写时不直接承诺、置信度用 PGIF 证据在可见 ID 上的 top1 − top2 差，走正常承诺规则(置信门限 + 5 tick 滞回)。设计 §5.2 只写了「置信度用证据差」,这里明确「不直接承诺」也属于该开关。
- **D6 OA-VAT 以帧计的参数换算为 S2 tick**:重捕获每 2 帧 → 每 tick;预测上限 15 帧 → 3 tick;在线增强每 20 帧 → 每 3 tick;速度历史 8 帧 → 2 tick;阈值(0.75 / 0.70 / IoU 0.2)、增强系数 0.8(`main.py` 默认)不变。原型参考 = 共享属性开局选中候选在 3× 开局帧上的「框外置零」图像 + 水平翻转(原仓库无掩码时的回退方式)。

## 发现 F14(冒烟中):目标的跟踪器 ID 被干扰车接管

- **现象**:U1(身份输出永远是真目标)在 93061 上旧口径正确率 1.0,新口径(policy 承诺)只有 0.25。逐 tick 记录显示：目标被遮挡时真值头只能弃权，承诺停在目标原来的跟踪器 ID(1 号)上;第 96 步起这个 ID 被跟踪器先后分配给干扰车(场景 actor 2、4、3)。原因：遮挡期间目标轨迹按图像平面匀速预测"滑行"(最多 8 tick),预测位置附近出现外观余弦 ≥ 0.2 的车就接过这个 ID。
- **影响**:
  1. 旧口径(输出身份 + scorer 自己的滞回)把弃权帧当作沿用上一承诺，完全掩盖了这一失败;新口径必须作为主指标(1006 §4 的修改得到直接验证)。
  2. 「目标 ID 被接管」发生在承诺层与跟踪器之间，身份模块再好也挡不住，是 C1(瓶颈在身份)的又一证据，也是 PGIF absent-hold 针对的情形。
  3. **U1 因此不是干净的上界**:它度量的是「身份输出完美，但承诺规则与跟踪器照常」。
- **建议的设计变更(待 codex 复审，未实施)**:增加诊断臂 U1′「承诺直接绑定真目标」(承诺与 WHERE 跟随真目标 actor,不经跟踪器 ID),作为真正的身份天花板;U1 保留，用来量化「ID 被接管」带来的损失(U1′ − U1)。
