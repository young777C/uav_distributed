## 2. 发现的不对称(按对谁有利分类)

### A. 对我们有利:PGIF 使用了模拟器的持久 actor ID,外部基线没有用
- **事实**:候选自带持久 ID `Candidate.idx`(目标为 −1,干扰车为编号),跨遮挡、出画、重新入画都保持不变。各方的使用情况:
  - 所有臂都在承诺滞回和 WHERE 中用到它。
  - **PGIF 用它按 actor 累积身份证据**(`policy.py:819`,`asd.py::_filter_step`),l5 / borrow#1 用它做时序分数(`policy.py:627–635`)。
  - **OC-SORT-style、DeepSORT-style、DAM4SAM、l4、xattn、TAHRelM 本体都不用**,要靠运动、外观或掩码自己完成跨帧关联。
- **性质**:这不是把「哪辆是目标」告诉模型(ID 本身不参与任何「是否为目标」的判断),而是**理想的数据关联层**。它是只有我们的方法用到的便利。
- **量化**(`rollout/id_persistence_audit.py`):
  - **开环回放**:在目标重新入画时强制换新 ID,相当于没有跨遮挡 re-ID 的真实跟踪器。PGIF 的增益仍保留 76%(TAHRelM,Town05)、91%(Town10HD)、68%(re-ID 记忆)。
  - **闭环日志**(§5.5 的 PGIF 臂):146 次纠正性改写(记忆选错 → PGIF 改对)中,92% 发生在目标持续可见期间,8% 发生在目标重新入画后 3 秒内。有害改写共 41 次,其中 32% 在重新入画后 3 秒内。
  - **结论**:PGIF 的增益**主要不依赖跨遮挡的完美 re-ID**,而是依赖**目标可见期间的理想短时关联**。真实跟踪器在 look-alike 车辆相互靠近时恰好容易发生 ID 互换。1001 §5.4 的开环噪声实验显示,每 tick 互换率 0.1 时增益基本消失。
- **现状**:1001 的局限 L1 写了「理想关联」,但**没有把它作为对外部基线的不对称说明**。

### B. 对我们有利:开发与调参的不对称
- 我们的方法在**同一组 19 个种子**上经历了多轮闭环开发和选型:ASD → PGIF-bayes → PGIF-tempered,λ、W,TAHRelM 的特征与 DAgger。外部基线没有调参。
- 承诺置信阈值 `--conf-tau`:我们的臂为 0.5,在开发中确定;外部基线统一为 0.05,沿用 re-ID 阶梯的值,没有针对各基线调过。
- **性质**:测试集复用 + 调参预算不对等,会系统性地偏向我们。
- **现状**:1004 预注册稿已通过「全新 test 种子 + 基线 dev 网格调参」修复,但 §5.5 本身仍是在开发种子上的结果。

### C. 可能对 DAM4SAM 不利:视频跟踪器被降帧使用 —— **已由 G11 排除(10-03 02:30)**
> G11(dev,n = 19)逐帧更新相对每 6 帧一次:
> - 承诺口径 −0.06 [−0.24, +0.13],严格口径 −0.00,均不显著;
> - 逐帧统计的空掩码仍有 69%,选中时准确率由 0.59 降到 0.48。
>
> 降帧不是 DAM4SAM 表现差的原因,§5.5 没有因此低估它。PGIF 相对逐帧版 DAM4SAM:承诺口径 +0.19 [+0.06, +0.34],严格口径 +0.39 [+0.22, +0.57]。数据:`eval_out/paper_it_damdiag_ef_g160.json`、`runs/asd/iter/damdiag_ef_g160_p1.jsonl`。
- 所有身份模块只在 S2 慢流中运行(`policy.py:552`,`--s2-period 6`,10 fps),即每秒 1.67 次。DAM4SAM 的 SAM2 记忆是为**逐帧视频**设计的,在本系统中相邻两次输入相隔 0.6 秒,无人机运动带来的位移更大。
- 这可能是它空掩码率高达 52–65% 的原因之一(`1003_iteration_roadmap.md` 的 DAM4SAM 弃权诊断)。**尚未验证。**
- 另外两点也可能偏向或不利于 DAM4SAM:它被限制为只能在候选框中选择;弃权时 WHERE 仍沿用上一个承诺车辆的真实世界坐标,这一点对它有利。

### D. 指标口径是看到结果后修正的
- 原口径(弃权算对)偏向 DAM4SAM(0.786)。改为承诺口径(0.367)的理由是与另两项指标一致,但修正发生在看到 DAM4SAM 的弃权现象之后。
- 1001 和 1003 中都已声明这是结果后修正,三种口径并列报告。

### E. 统计与批次
- 每臂只跑一次,n = 19。
- 同配置 A/A(DAM4SAM 两次运行):三种正确比例都能复现,但**最长锁错相差 10.6 s 且显著**。因此 §5.5 中「PGIF 最长锁错比 DAM4SAM 少 11.3 s」落在运行间噪声的量级之内,不能作为方法差异的证据。
- 各臂分布在 3 台 CARLA(2000 / 2010 / 2040,不同 GPU)上,没有交错调度。可能存在服务器效应,未评估。

## 3. 自查结论

1. **严格意义上的作弊(决策中使用真值):没有发现。** 所有真值使用都只在日志、诊断或 gt 模式分支中,deployable 臂的启动参数正确,代码版本一致。
2. **但 §5.5 并非完全对等**:
   - 有两项不对称**偏向我们**:A,PGIF 独享理想 tracklet 关联;B,开发与调参都在同一批种子上进行。
   - 有一项**可能偏向不利于 DAM4SAM**:C,降帧使用。
   - 指标口径是结果后修正的(D),最长锁错的运行间噪声很大(E)。
3. **因此 §5.5 中「PGIF 优于 DAM4SAM」的表述应降为暂定结论。** 正式结论以 1004 预注册方案在全新 test 种子上的结果为准。

## 4.5 更正(2026-10-03 00:10):候选集与「目标在画面内」都**不考虑遮挡**

- `candidates.py::_mk` 只检查目标或干扰车投影后是否落在图像范围内,`env.py:175` 的 `target_present` 也只按视锥判断。两处都没有做遮挡(射线)检测。
- 因此,**目标被建筑物或其他车辆挡住时,只要还在视锥内,它的候选框(按真值位置投影的伪框)和 actor ID 就一直存在。**
- 对第 2 节的影响:
  - **A 比原先估计的更强**:`id_persistence_audit.py` 的「重新入画」只覆盖出视锥再回来的情况。画面内遮挡期间,候选和 ID 根本不会中断。所以「92% 的纠正发生在目标持续可见期间」中的「可见」应理解为「在视锥内」,其中包含被遮挡的时段。
  - **对 DAM4SAM 的弃权诊断要修正**:「目标在画面内时 52–65% 为空掩码」里,有一部分帧目标其实被遮挡。这时 SAM2 判定目标不可见是**正确的**,而 scorer 仍按「目标在画面内」计入。严格口径会因此惩罚 DAM4SAM;承诺口径沿用上一个承诺,影响较小。比例未量化。
- **补救**:在 env 里加入基于射线的目标可见性标志(CARLA `world.cast_ray` 或语义分割),写入 scorer 和逐 tick 日志。各项指标按「可见 / 视锥内但被遮挡」分开报告。列入 1004 T0(G13)。

## 6. 联合结论

1. **没有作弊**:deployable 臂的决策链路没有读取真值,候选顺序没有泄漏目标槽位,启动参数正确。
2. **§5.5 不是「同等接口、同等工程预算」下的公平比较**:
   - 偏向我们的有:A,PGIF 独享理想 tracklet ID;B,开发种子复用、基线未调参,`conf_tau` 0.5 对 0.05;G,PGIF 强制置信。
   - 可能对 DAM4SAM 不利的有:C,降帧。
   - 统计口径不干净的有:F,超时 episode 仍被计分;E,单次运行;H,溯源不足。
3. **§5.5 的结论应改为以下表述**(采纳 codex 建议):在理想候选框、理想持久 tracklet ID 和理想定位接口下,TAHRelM + PGIF 在 Town05 开发种子上,相对 TAHRelM 无纠偏及若干未调参的基线,提高了承诺口径正确锁定比例和最长连续正确锁定。相对 DAM4SAM 的优势处于边界或不显著,并受口径修正、DAM4SAM 降帧、开发种子复用和理想关联接口影响。正式结论以 1004 预注册实验为准。

**结论(如实)**:
1. **把理想感知换成真实感知后,§5.5 中 PGIF 的增益消失。**
   - 下降的大头来自遮挡感知:旧 V0 → B,正确比例 0.576 → 0.365,最长连续正确 21.3 s → 4.5 s。
