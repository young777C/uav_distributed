**必须修改**

1. **§4.3 把“坐标补偿”说得太强**
问题：地面坐标系/相机运动补偿只能去掉图像坐标偏差，不能让非目标事件自动等价于目标事件。目标与非目标的核心差别是策略生成机制不同：专家主动让目标留在画面里；目标丢失后，无人机的运动又由“认为目标在哪”驱动。非目标事件没有这个 WHICH→WHERE/HOW 闭环。
证据：v5 中非目标开始丢失时目标仍可见比例约 92%；目标 ≥3s 重入时左右边缘 0%，相似车 34%、普通干扰车 59%。这不是单纯相机坐标偏差，而是采样/控制策略偏差。
改法：§4.3 应降级为“补偿后可用于世界运动预训练和辅助 re-ID”，不能写成“让非目标可迁移”。训练上应分三类：目标事件用于主训练/主测试；非目标平衡混入用于身份/运动先验；控制策略只用真实目标或离线 retarget 后重算专家动作的数据。

2. **瞬移统计可信，但草案必须补清口径**
问题：`runs/data_audit/event_census.py` 和 `event_census_v5.json` 本身没有计算瞬移，草案直接写 43% 证据不完整。
证据：我用 h5 的 `distractors/positions[:, :, :3]` 复核，口径为相似车 ≥3s 重入事件中，gap/reentry 窗口内任意相邻帧 xy 位移 `>5m`。结果是 **80/185 = 43.2%**；若只看“最后不可见帧→重入帧”，是 **69/185 = 37.3%**。普通干扰车同口径为 0/209。  
改法：§1 改成：“按 h5 世界坐标相邻帧位移 >5m 检测，80/185 相似车 ≥3s 重入事件含瞬移；其中 69/185 发生在重入边界。” “来自共视回收”应写成基于代码机制的推断，而不是 JSON 直接统计。

3. **不能简单建议关闭共视回收**
问题：关闭回收会净化运动先验，但会把论文最需要的“相似车共视/语言消歧杀手场景”打没。
证据：v5 当前开启回收时，目标可见帧里 ≥1 相似车共视 76.1%，≥2 相似车共视 58.8%。旧 MVP 数据卡写明回收关闭时 ≥2 相似车共视只有 13.6%。v6 smoke 的强制共视可到 72–92%，但目标重入事件仍很少。
改法：不要写“关闭共视回收”作为默认方案。应改为：瞬移事件标记并从运动学习剔除；语言消歧评测可保留但单列 teleport flag；长期方案是平滑 station-keeping、同路段 convoy/邻车道物理生成，或 loss-window 结束前几秒把相似车自然引入视野，而不是帧级瞬移。

4. **背景车 actor 级标注的收益被写得过乐观**
问题：每帧几十辆背景车做投影本身可行，但“投影 + 实例关联 + 稳定身份事件”不是零成本。v6 的 `traffic/blobs` 只保留最大 32 块，本来就不适合 actor 级重入统计；全背景实例关联会引入远处小车、遮挡碎片、mask 抖动。
证据：v6 已有 `actors/*` 给目标+干扰车做 per-actor 标签；`traffic/blobs` 平均每帧满 32 个，说明它是 top-K blob 视图，不是稳定 actor 表。
改法：不要承诺“完整背景车 actor 级标注”是主方案。更便宜的替代：只记录 CARLA actor handle 的世界状态和投影框；只对半径内/投影面积超过阈值/稳定可见超过 N 帧的背景车建事件；实例 mask 只用于可见像素与 modal box，不用于所有背景车长期身份主标签。

5. **事件索引层“只存索引”会拖垮训练**
问题：只存 event→h5 frame index 对评测和审计很好，但对训练不够。随机事件窗口会导致大量 gzip RGB/h5 小块随机读；TAH/PGIF 类训练还需要候选特征序列，在线从 h5 和 VLM cache 拼会重复 IO。
证据：现有 Stage-2 已经专门用 `train/backbone_kv.py` 预计算 VLM context，并用 `train/mmap_cache.py` 转成 mmap；TAH 也已有 `runs/tah_cache.pt` 这类离线特征缓存。说明管线已经被 IO/特征提取逼到缓存化。
改法：保留“事件索引 manifest”，但新增离线事件特征层：candidate crop/box pooled features、世界坐标、bbox、visible、tracklet、source、teleport flag、label。RGB 仍留完整 episode，训练优先读 mmap/zarr/pt shard 特征。

6. **§5 验证顺序应前移“无重生成可做”的部分**
问题：草案把全量生成和训练消融放得太早，容易卡在数据生产。
证据：v5+h5+现有闭环日志已经能回答不少风险问题。
改法：先做这些不重生成实验：v5 事件审计加 teleport filter；非目标事件按目标可见/边缘重入/gap 分层；已有闭环日志按 cold-start、ID switch、reacq success、wrong-lock duration 分解；随机 h5 事件读取 vs 离线特征 cache 的 IO benchmark；用 v5 现有目标+干扰车构建 TAH/re-ID 离线 all-actor cache 做身份消融。控制 retarget、背景车 actor、关闭/替代回收后的产量评估，再放到 v6.1 之后。

**可以保留**

- “标注所有车辆能显著放大事件量”可以保留，但必须强调是辅助样本，不是同分布目标样本。
- 双层结构可以保留：完整 episode 层 + 事件索引/特征层。
- 主评测只用目标事件、持久 actor ID 只给 scorer、tracklet 必须断开，这些是对的。
- 创新性定为“中”可以保留；“Sticky-ID 零假设/评测协议诊断”反而是比较稳的贡献点。

**最稳贡献表述**

我们提出一个面向 UAV 语言指定跟踪的事件中心数据与评测协议，将完整闭环 episode 重组为断开 tracklet 后的目标重捕获、缺席误认和相似车共视事件，并显式区分持久 actor ID 与模型可见 tracklet。  

该协议揭示了持久 ID 与相机/专家策略会显著高估重捕获能力，并提供平衡的目标事件、非目标辅助事件和 target-absent 负样本来训练与评估语言身份延续。
