## 2. 定义

### 2.1 Pr / Re / F(S2 tick 粒度)

沿用 1019 §2.1 的 tick 状态(`gates/metrics.py` 的 `fine_status`)。

- **Re**(召回):目标有框的 tick 中，状态为 follow 的比例。**与 M1 完全相同**。
- **Pr**(精确):承诺的 key 本 tick 有框的 tick(follow 或 misled)中,follow 的比例:
  $$\text{Pr}_i = \frac{n^{\text{follow}}_i}{n^{\text{follow}}_i + n^{\text{misled}}_i}$$
  - 统计**所有 tick**,不论目标是否在画面内。目标出画时，承诺的框若是干扰车，同样记为错误(无人机此刻正飞向错车)。这是 Pr 与 M2 的关键区别。
  - stale、none(承诺的 key 本 tick 无框，或未承诺)不进 Pr 的分母，只在 Re 中计为未跟随。所以撤销承诺不损害 Pr,但会损害 Re。
  - 分母为 0 的局，Pr 无定义，记录其局数。
- **汇总(仿照 VOT-LT)**:先按局平均得 Pr、Re,再算 $F = 2\,\text{Pr}\cdot\text{Re} / (\text{Pr} + \text{Re})$。Pr 只在有定义的局上平均。
- **与 VOT-LT 的差异(须在论文中注明)**:VOT-LT 对置信阈值 τ 扫描、取 F 的最大值;我们的承诺规则(conf_tau + K = 5 迟滞)是所有方法共享的固定工作点，只报这一个点的 F。
- **护栏**:按 tick 合并的 Pr / Re / F($\sum n^{\text{follow}} / \sum(\cdot)$),放附录。

### 2.2 RA 曲线与 AUC

- 事件、截尾、成功时刻 $t^\*$ 与 `runs/stress/reacq_metrics.py` 相同(L = 2 tick,W = 10 tick,Δ = 0.6 s)。
- $\text{RA}(w)$ = 未截尾事件中 $\text{TTR} \le w$ 的比例,$w \in \{0, 0.6, \dots, 5.4\}$ s。$\text{RA}(5.4) = \text{RA@6s}$。
- $\text{AUC} = \frac{1}{10}\sum_{m=0}^{9} \text{RA}(0.6m)$。由于 TTR 只取 0.6 s 的整数倍、失败计为 6 s,**AUC 恰好等于 1 − RMTR / 6**,两者择一报告。
- 曲线图注须写明:换 key 事件受 K = 5 迟滞限制，在 2.4 s 之前所有方法都不可能成功。

### 2.3 FRA@6s 及其成因分解

- **主指标 FRA 取端到端口径**(= 现 WL@6s):窗口内、成功之前出现过 misled 的事件占比。理由：无人机此刻确实在飞向错车;所有方法共用同一个跟踪器，这个口径对各方法公平。
- **成因分解只作辅助分析**。看窗口内第一个 misled tick 时承诺的 key:
  - **跟踪器转手**:承诺的 key 与丢失前相同，且该 key 以前对应过目标(跟踪器把目标的 key 接到了别的车上);
  - **丢失前已错**:承诺的 key 与丢失前相同，但该 key 从未对应过目标;
  - **身份头改选**:丢失后承诺换成了另一个 key。
- U1 的身份头取真值，所以 **U1 不是 FRA 的下界**(见 §4)。

3. **K = 5 迟滞要求同一个挑战者连续 5 票**。key 一抖动，选票就分散到几个 key 上，真值身份头也换不过去。

4. **对指标的含义**:FRA 是跟踪器与身份判断的合力，在自主飞行下尤其如此。论文中 FRA 须附成因分解;U1 不能作为 FRA 的下界引用;自主飞行下以 U1 为参照的目标值(如 target_m1 = 0.810)也同样受此上限影响。
5. **对方法的含义(不属于本预注册，仅记录)**:自主飞行把目标飞远是 key 抖动的上游原因，与 10-19"飞行是 TR90 主瓶颈"一致。

## 7. 指标独立性审核(10-23,§6 之后;codex 与 Claude 各自独立计算)

**起因**:PI 要求主指标相互独立，依赖其他指标的视为冗余。
**材料**:codex 原文 `runs/stress/codex_metric_independence_1023.md`;Claude 的计算 `runs/stress/metric_redundancy.py`。两边结论一致。

### 7.1 定义层面

| 关系 | 结论 |
|---|---|
| F 与 Pr / Re | **确定性函数**:$F = H(\text{Pr}, \text{Re})$,逐局 $F = 2|C| / (|V| + |C| + |B|)$ |
| AUC 与 RMTR | **恒等**:AUC = 1 − RMTR / 6 |
| RMTR 与 RA@6s | RMTR = 6(1 − a) + a·μ,其中 a = RA@6s,μ = 成功事件的平均 TTR。所以 RMTR 是成功率和速度的混合,0.1a ≤ AUC ≤ a |
| RA 与 FRA | 分母相同，但两者不互补:"先错后成功"的事件回放中有 34 个、自主飞行中有 21 个 |
| TR 与身份指标 | TR = (在画面内帧数 / 900) × pc_correct,与 F、RA、FRA 都不能互相推出 |
| Re(M1)与 RA | Re 的分母中约 20% 的 tick 落在重新捕获窗口内。去掉窗口内 tick 后的 Re_hold 与 RA 的相关只从 0.77 降到 0.72:未能找回会让窗口之后的 tick 继续不跟随，所以这是因果上的依赖，不是 tick 重叠造成的 |

### 7.3 修订建议(待用户拍板;**未改动 §1–§4 的预注册原文**)

| 主指标 | 覆盖的问题 |
|---|---|
| **TR** | 整体端到端跟随 |
| **Pr** | 无人机有目标可飞时，飞的是不是对的车(身份保持) |
| **RA@6s** | 丢失后能否找回 |
| **FRA@6s** | 找回过程中是否跟错车(安全) |
| (可选)**成功事件平均 TTR** | 找回有多快。须注明只统计成功事件,存在选择效应,且受 K = 5 迟滞下限约束 |

**降为诊断(有依赖，不能当作独立证据)**:Re(= M1)、F、RMTR / AUC 曲线、承诺正确、FRA 成因分解、换 key 子集的 RA。

**关于偏离预注册的透明说明**
- 理由只涉及结构冗余，不涉及哪个方法赢。
- 改用 Pr 后,Ours-CV(旧 TAH)相对 re-ID 反而更差:Pr 差 −0.066,显著;Re 差 −0.026,不显著。(§7 的相关分析只用了 10-23 的 7 / 5 个方法，不含重训版。)
- 10-19 的主指标 M1 将退为诊断项;test(950xx)仍未使用。
- 剩余的最大两两相关是 Pr – FRA,约 −0.5 到 −0.6,两者都计 misled。若要再压低，可改报窗口外 Pr($P_Q$,codex §C)。但总体 Pr 是分区 Pr 的加权平均，分区本身并不能带来统计独立。

### 8.1 主指标(4 个)

| 主指标 | 类型 | 回答的问题 | 表 A 专家回放 | 表 B 自主飞行 |

  - 与 10-19 预注册的主指标、第 0 步的上限判定、autotune 的 target_m1 保持连续;
  - M1 单独看不会偏向保守方法;
  - 自主飞行下,M1 与其他主指标的相关(0.07–0.37)低于 Pr(最高 0.64)。
- **代价(须在论文中如实说明)**:
  - 回放下 M1 与 RA@6s 高度相关(逐局 0.77,配对差 0.81),表 A 中两者不能算作两份独立证据;
  - 窗口外的跟错车(占跟错 tick 的 67%–92%)没有主指标覆盖，由诊断项 Pr 补上。
- **M1 的已知偏差**(1019 §2):按局平均会放大短局的权重。护栏是按 tick 合并的 M1,放附录。
