# re-ID 线 · 概念答疑 FAQ

> 记录日期：2026-09-03 · 汇总讨论中提出的关键概念问题 + 简答 · 配套 `reid-line-summary.md` / `reid_final_architecture.html` / `reid_dinov2_gallery_pipeline.html`

## Q1. 什么是 reid（重识别）？
判断"现在看到的目标是不是我之前跟丢的那一辆"——靠**外观特征匹配**,不是靠"符不符合语言描述"。
- 旧法(语言 tid):每帧问"哪辆最像『黄 SUV』"→ look-alike 都满足 → 易错;
- reid:跟踪时**记住目标外观**(存成图库),重现时选**和记住的那辆最像**的。先用过去图库选、再更新(无 GT 泄漏)。

## Q2. 什么是 DINOv2？为什么能有效提升？
Meta 2023 的**自监督视觉基础模型**(无标注、无语言,自蒸馏训 1.42 亿图),特征**实例判别**(抓纹理/形状细节),而非语义。
- **VLM(Qwen)特征**是语义/语言对齐 → look-alike 看着一样(余弦 0.88);**DINOv2**抓视觉细节 → 分得开(0.61)。
- **有效的机理(三个正交子问题)**:① crop-DINOv2 修**特征可分性**(用满 24px 车像素,而非池化成 1 格);② K 视角图库修**视角鲁棒性**;③ 置信门控修**控制耦合**。

## Q3. 什么是专家取景（expert-control）？为什么是"可解上界"？
harness 的 `--expert-control`:**控制由"知道目标真值的 GT+PID"驱动**(把目标完美框在画面中央),但**认车仍由策略做**(只打分)。
- 它人为去掉了 WHERE+取景的所有失败 → **测"如果取景完美,认车能不能成功"**;
- 实测 SR≈**0.11** = 取景完美时的天花板(你不可能比完美取景更好)→ **可解上界**;
- 但它是**相对当前认车能力**的上界,不是物理硬极限(更强认车/更高分辨率会抬高它)。

## Q4. SR 如何判定？（见 `metrics.py`）
逐帧维护 **committed 目标**(pick 经 K=5 帧滞回)+ 两个连续计数器。两条失败线:**认错车 ≥2s** 或 **出画 ≥5s**。
```
success = (从未认错车≥2s) 且 (结束时未出画≥5s)
```
SR = 成功集 / 有效集。0.105 ≈ 19 集里约 2 集全程无差错跟对。

## Q5. WHERE 阶梯（ear→cv_gated→road→road_oracle）如何一步步改进？"近乎完美"是什么标准？
WHERE = 预测目标出画后在哪、好飞过去拦截,填 DiT 的 z_ex。
- **ear**:反应式单帧,目标已出画→盲猜(FDE 58–90m);
- **cv_gated**:记忆最后可见位+速度,直线外推(直路 10–23m,转弯崩 36–48m);
- **road**:沿车道遍历(补转弯,但可部署分支选错);
- **road_oracle**:锚点换成**目标真实当前位、每帧刷新**(仿真真值)→ **近乎完美**。
- **"近乎完美"的标准** = WHERE 先验被锚定到 **ground-truth 目标当前位置且每帧刷新**(特权,现实不可得),残余仅 1–6s 短程前瞻。
- **结论**:即便 WHERE 近乎完美,SR 仍 0、lock_wrong 仍 ~0.74 → **墙是 WHICH 不是 WHERE**。

## Q6. 不提分辨率,还有哪些提升方式？
三个攻击面:**(I) 从同像素榨更好特征**(crop-DINOv2 / re-ID骨干 / 多层部件 / 度量学习);**(II) 融合别的线索**(运动关联复用CV / 颜色直方图 / 集合关系 / 时序);**(III) 主动感知**(飞近换角度=用距离换分辨率)。→ 首选 crop-DINOv2(既提升又诊断"信息在不在像素里")。

## Q7. crop-DINOv2 vs VLM 网格池化,分别怎么实现?为什么这么设计?
- **VLM 池化**:Qwen 出 16×16 网格,24px 车框只覆盖 ~1 格 → 混背景/语义/丢细节 → 余弦 0.88;
- **crop-DINOv2**:从**原图裁车像素**→resize 224→DINOv2 → 车得 ~196 个 patch token(而非 1)→ 捞回被池化丢的身份细节 → 0.61。
- **设计动机**:0.88 高一半是"像素少"、另一半是"仅有的像素被池化用糟了";crop-DINOv2 专修后一半(**免费,不重渲**),兼诊断"像素够不够"。

## Q8. 多视角是什么?为什么需要?多少帧合适?
- **是什么**:存目标**多个视角**的单帧快照成一个图库(gallery),重现时匹配**最像的那个视角**——不是"喂多帧给模型",是"记多张快照、拿当前帧比对最像的";关键是**分开存**而非平均。
- **为什么**:DINOv2 视角敏感(同车换角度 self 0.91→0.71),单模板对不上重现新角度 → 图库让当前视角总能对上库里某个。
- **多少帧**:不是越多越好——甜点 **K≈2–3**(过多→干扰车碰运气撞某视角,margin 反被侵蚀);按**多样性**挑(非连续帧)+ top-m 匹配。离线实测 K=2 最佳(mis_follow 破 0.5)。

## Q9. "track" 是什么?reid 为什么会连到 WHERE?
- **track** = 一种控制接线(`ex_source=track`):**reid 认定的那辆车**驱动控制(取它位置做 CV → z_ex → 飞过去),而非 cv_gated 用 GT 目标当 z_ex。
- **reid 本身是 WHICH(认哪辆)**;但 track 下,认定结果**顺带决定 WHERE**(飞向那辆车)→ WHICH 和 WHERE 耦合。认错→飞错→丢目标,故需置信门控。

## Q10. EAR 被覆盖了,还需要吗?
最终 track 配置**推理时冗余**:z_ex 每帧被"认定车 CV"覆盖,EAR 白算,`--ablate ear` 删掉无影响。它只在**训练时**(塑造了 DiT)和 `ex_source=ear` 时有用。

## Q11. "承诺（K滞回）+ 置信门控"是什么?
认车→控制路径上的两道稳定阀:
- **承诺+K滞回**:锁定的身份不每帧变,挑战者要**连赢 5 帧**才夺锁(防抖动);
- **置信门控**:pick 的 margin(top1−top2)低时**不切换、不飞、惯性递推**(防认错丢目标)。

## Q12. 什么是"候选框 GT位投影"?
把画面里所有车的**真值三维世界坐标经相机投影**成 2D 框(`candidates.py`),当作"检测器给的候选"。**只给车在哪(位置),不给哪辆是目标(身份,无标签+打乱)**;`true_idx` 只给打分器。是车辆检测器的**特权替身**,干净隔离 WHICH 问题。

## Q13. VLM / IAR / DiT 各实现什么功能?
- **VLM(Qwen,冻结)**:看懂画面+语言 → 共享表征 `vlm_ctx` + 特征网格(供池化候选);感知底座。
- **IAR**:逐层 query VLM → 紧凑视觉理解 token `z_im` + occ(遮挡)/maneuver(机动)辅助头;"目标视觉上怎么样"。
- **DiT(扩散动作头)**:融合 z_ex(去哪)+z_im(视觉)+vlm_ctx(场景)+proprio(自身)→ **飞行动作**;**唯一控制器**,故"核心控制仍是 DiT"。
- (EAR:预测目标未来轨迹 z_ex,最终被 CV 替换;tid:语言认车,被 reid 替换。)
