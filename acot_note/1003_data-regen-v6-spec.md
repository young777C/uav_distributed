# 1003 · v6 数据集重新生成规格(uavtrack_v6_fov90,当前版本 v6.1)

> 2026-10-03 · 依据:`1003_data-check.md`(数据审计 v2)、`codex/1003_data_regen_R1.md`(生成前审核,结论:补充要求后再生成)。
> 研究范围:**只做白天、无雾场景**。
> 目标:以 Stage-2 实际训练为准(FOV 90°),生成一份标签尽量完整、可追溯、能支持后续"真实关联 / 遮挡 / 未见城镇"评测协议的数据集。

## 1. 与 v5(含 09-04 重新生成版)的差异

| 项 | v5 重新生成版(09-04) | **v6** |
|---|---|---|
| 相机 | 512²,FOV 70°(与训练投影、闭环都不一致) | **512²,FOV 90°**,俯仰 −50°,与 Stage-2 原始 v5 和闭环一致 |
| 天气 | 默认随机(白天、无雾) | 在场景配置中**显式写明**:太阳高度 15°–70°,雾 0 |
| 子集 | 单一 mvp | **base / reacq / occ** 三个子集(§2) |
| 城镇 | 5 个都进训练集 | 5 个训练城镇 + **Town03 只用于测试**(Stage-2 原始 v5 也没见过) |
| 目标标签 | 伪方框、出画、遮挡比例 | 保留,并新增目标与每辆干扰车的**投影 3D 框、深度、光线投射遮挡、实例分割可见框、可见像素数、实例 ID** |
| 身份标签 | 只有持久 actor 编号 | 新增按可见性间隔**会断开的 tracklet ID**,以及**目标重新入画事件**表 |
| 场景外交通 | 不标注 | 每帧最多 32 个车辆像素块(实例 ID、类别、框、像素数),外加实例掩码 |
| 元数据 | 语言、城镇、种子等 | 另写 fov、分辨率、标签版本、子集、episode_id、配置快照、git commit、dirty 补丁哈希、CARLA 版本、生成命令 |
| 后处理 | FOV 写死,默认 90 | 从 attrs 读取 FOV,缺失或不一致直接报错 |
| 划分 | 划分文件缺失,静默按文件名切分 | 质检后生成真实存在的划分文件;Town03 作测试集 |
| 可追溯 | 无 | 数据目录下保存 `provenance.json`、`code_snapshot.patch`、`code_untracked.tar.gz`、`plan.json` |

## 2. 子集与规模(full plan,500 集)

| 子集 | 场景文件 | 特点 | 训练城镇(每城镇集数) | Town03(测试) |
|---|---|---|---|---|
| base | `config/scenarios/v6_base.yaml` | 复刻原始 v5 / `mvp.yaml`:4–8 辆干扰车,≥ 2 辆相似车,每集 2 次制造丢失(4.5–6.5 s),150 s | 01/02/04/05/10HD 各 40 → 200 | 20 |
| reacq | `config/scenarios/v6_reacq.yaml` | 每集 4 次制造丢失(5–9 s),≥ 3 辆相似车,丢失结束时强制相似车共视,180 s | 各 30 → 150 | 20 |
| occ | `config/scenarios/v6_occ.yaml` | 引导目标驶入桥下、立交下等结构遮挡(bias 0.8),每集 1 次制造丢失,150 s | 05/04/10HD 各 30 → 90 | 20 |

- **合计:** 500 集,其中训练城镇 440 集、Town03 60 集。预计约 75 万帧、约 330 GB。
- **episode_id 与种子:** episode_id = 子集基数(100000 / 200000 / 300000)+ 城镇编号 × 1000 + k;种子 = episode_id。与评测种子(90000–96000)不重叠。
- **磁盘保护:** 剩余空间低于 250 GB 时,调度器停止派发新任务。任务按"子集 × 城镇"轮转排队,所以中途停下时各子集和城镇的分布仍然均衡。

## 3. h5 字段(v6 新增部分;v5 原有字段全部保留)

| 字段 | 形状 / 类型 | 含义 |
|---|---|---|
| `actors/ids` | (A,) int32 | CARLA actor 编号;索引 0 为目标,其后是干扰车,顺序与 `distractors/*` 一致 |
| `actors/role` | (A,) int8 | 0 目标,1 相似车,2 其他干扰车 |
| `actors/in_frame` | (T,A) uint8 | 3D 框中心的投影是否在画面内 |
| `actors/amodal_box` | (T,A,4) float32 | 3D 包围盒 8 个角点投影后的外接框,裁剪到画面内,格式 x0,y0,x1,y1;−1 表示无 |
| `actors/depth` | (T,A) float32 | 中心点到相机的深度(m) |
| `actors/occ_raycast` | (T,A) float32 | 包围盒角点射向相机、被几何体挡住的比例;投影框不存在时为 NaN |
| `actors/inst_id` | (T,A) int32 | 关联到的实例分割 ID(CARLA 中稳定且唯一,但不等于 actor ID);−1 表示未关联 |
| `actors/vis_px` | (T,A) int32 | 可见像素数 |
| `actors/modal_box` | (T,A,4) float32 | 可见像素的外接框 |
| `actors/visible` | (T,A) uint8 | 后处理生成:`vis_px` ≥ 20 |
| `actors/tracklet_id` | (T,A) int32 | 后处理生成:不可见 ≥ 10 帧(1 s)后再出现时换新 ID;不可见时为 −1 |
| `events/target_reentry` | (K,5) int32 | 目标在不可见 ≥ 10 帧后重新可见的那一帧;列:frame、gap_frames、cause(0 出画 / 1 遮挡 / 2 混合)、可见相似车数、可见场景车辆数 |
| `traffic/blobs` | (T,32,7) float32 | 场景外车辆像素块:inst_id、类别、x0、y0、x1、y1、像素数;−1 为填充 |
| `instance_mask` | (T,H,W) uint8 | 0 背景,1..A 场景车辆,254 其他车辆,253 行人 |
| attrs | — | `fov`、`rgb_resolution`、`fps`、`label_version`、`subset`、`episode_id`、`config_snapshot`、`scenario_file`、`seed_base`、`git_commit`、`git_dirty_sha256`、`carla_server_version`、`test_town`、`train_towns`、`v6_*` 后处理参数 |

**实例关联方法:** CARLA 0.9.15 的实例 ID 不等于 actor ID(10-03 探针已验证)。做法是把场景车辆的投影 3D 框与实例像素块按像素重叠贪心匹配,且要求一个像素块至少 50% 的像素落在该投影框内,避免把相邻的遮挡车误认成目标。新生成的车辆约 30 tick 后才会出现在实例图中,录制器在正式录制前有 90 tick 预热,不受影响。

## 4. 质检门槛(`runs/data_v6/qc_v6.py`;不通过的 episode 不进入划分)

- **G1 attrs:** 必需字段齐全,且 fov 为 90。
- **G2 图像:** RGB 形状为 (T,512,512,3),T ≥ 300;抽 16 帧,没有全黑帧。
- **G3 投影与实例对齐:** 在可见像素 ≥ 50 的车辆帧中,≥ 95% 的可见框有 90% 以上面积落在投影框内(留 3 px 余量)。FOV 或位姿一旦错配,这项会直接不通过。
- **G4 关联率:** 在"明显可见"的车辆帧中(投影框边长 ≥ 12 px、遮挡比例 < 0.2、中心在画面内),≥ 85% 能关联到实例像素块。
- **G5 后处理完整:** `actors/visible`、`actors/tracklet_id`、`events/target_reentry` 都已生成。
- **数据集级报告:** 按子集 × 城镇统计帧构成、重新入画事件(≥ 3 s 后、有相似车在场)、相似车共视率和目标框尺寸。
- **划分规则:** test 为 Town03;val 为训练城镇中 `episode_id % 10 == 9` 的集;质检不通过的排除。

## 5. 流程

1. **冒烟测试:** 每个子集各 1 集,另含 1 集 Town03。跑质检 + 可视化,确认实例关联、遮挡生效、元数据完整。
2. **Codex 审核:** 审实现和冒烟测试结果。
3. **批量生成:** full plan,4 个专用 CARLA 槽位,端口 2100/2110/2120/2130,分别在 GPU 1/0/2/3。不占用共享评测端口 2000–2060。
4. **全量质检、生成划分文件,并更新数据卡。**

## 8. v6.1 第二批修订(2026-10-03,Codex 实现审核 R2 `codex/1003_data_v6_impl_R2.md`:修复后再生成)

R2 确认 R1 的工程问题已修好:原子写入、目录锁、原始实例图、3D 字段、近裁剪都已落地。但它用当前质检复核 smoke2–4,没有一集正式文件通过。根因是**场景本身跑不出目标分布**。逐项排查与修复:

| 问题 | 根因(冒烟实测) | 修复 |
|---|---|---|
| 目标大面积静止 | 背景车生成在离目标**最近的 N 个出生点**,再加"休眠车在主角附近重生",开局即把目标围在车队里;CARLA 默认 4 路口红灯 30–45 s;目标车禁止变道,前车不走就永远卡住 | `scene.ambient.spawn_mode: ring`(在 30–200 m 环内随机选出生点),背景车 80 → 40、半径 90 m;`scene.traffic_lights` 设为绿 6 s / 黄 2 s;`scene_actors_lane_change: true`;目标连续 40 s 移动不足 5 m 即截断 |
| reacq 造不出丢失 | 目标不动时悬停也没用;固定窗口太短 | 悬停**自适应延长**:窗口结束时,如果目标出画还不满 3 s 就继续悬停,最多 15 s;延长期同样标记 `action_valid=0` |
| G9 规格与实现不一致 | 规格写 50%,代码写 40% | 统一为 50%(修场景,不降门槛) |
| 选择偏差无记录 | 拒收集只保留文件,没有汇总 | `qc_v6.py --reject-report` 生成 `reject_report.json`(按子集 × 城镇统计拒收数与原因);随数据卡发布;任一子集 × 城镇拒收率 > 50% 必须调场景或在论文中声明 |
| 分布改动影响与 v5 的可比性 | 忽略红绿灯、背景车密度、只用轿车、悬停式丢失都改变了分布 | `dataset_version = v6.1_controlled_day_caronly`;关键开关直接写入 attrs(`ignore_lights_pct`、`lane_change`、`ambient_vehicles`、`ambient_spawn_mode`、`traffic_lights`、`loss_expert_mode`、`geometry_avoidance`、`target_class_policy`)。**论文中把 v6.1 定位为新的受控 benchmark,不称其为 v5 的等价复刻**;v5 只作历史参考 |

**磁盘保护**:R2 指出 `generate_batch.py` 的大小统计漏算 `.rejected.h5` 和 `.tmp.h5`。实际起作用的是调度器按 `shutil.disk_usage` 判断剩余空间(低于阈值就不再派发新任务),所以不受影响。

**冒烟验收标准(R2)**:同一 commit、空目录连续两轮冒烟,各子集 × 城镇通过率 ≥ 70%;reacq 每集至少 1 次"≥ 3 s 后重新入画且有相似车在场";occ 每个城镇至少 2/3 通过。达标后才启动全量生成。
